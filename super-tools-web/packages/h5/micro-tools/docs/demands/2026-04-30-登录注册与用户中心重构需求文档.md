## 一、需求概览

### 1.1 背景

`super-tool-node` 后端已在 v2.2.0 完成「全平台认证系统」与「会员等级体系」改造，新增 14 个认证接口、12 个用户/设备接口、6 个 C 端会员接口。
当前 `super-tools-web/packages/h5/micro-tools`（H5 移动端）仅对接了最早期的「账号密码登录 + 邮箱注册 + 基础资料查看」共 6 个接口，且：

- 未支持手机号验证码登录、账号绑定、设备管理、会员体系等
- 个人信息页仅展示基础字段，无任何编辑能力
- 设置页仅本地 UI 偏好，未对接任何后端用户配置
- 未实现路由守卫、Token 401 自动刷新等基础能力
- `service.ts` 直接以参数形式手动注入 token，与后端 Bearer Token 规范不匹配

### 1.2 需求目标

完整重构 micro-tools 的「登录注册」、「个人信息」、「用户设置」三大模块，并补齐底层鉴权基建：

1. **多入口登录注册**：手机号验证码（主入口）+ 账号密码（兼容入口），注册支持手机号一键注册或邮箱传统注册
2. **完整资料管理**：基础资料 + 扩展资料编辑、邀请码、会员卡片入口
3. **统一设置中心**：账号安全（密码/绑定/设备）+ 偏好设置（语言/时区/隐私/通知）+ 显示偏好（保留现状）
4. **健壮的鉴权基建**：请求拦截器自动注入 Token + 401 自动刷新 + 路由守卫 + 错误码统一映射

### 1.3 范围（IN / OUT）

| IN（本期实现） | OUT（不在范围） |
|---|---|
| 手机号验证码登录/注册 | 微信小程序登录（micro-tools 是 H5 项目，不涉及） |
| 账号/邮箱/手机号密码登录 | 微信公众号 H5 登录（V2 增强，本期暂不接入） |
| 邮箱注册（保留兼容） | Apple ID / Google / GitHub 等第三方登录 |
| 用户基础资料 + 扩展资料编辑 | 实名认证 |
| 邀请码展示与复制 | 付费购买流程 |
| 会员等级卡片入口（仅展示，详情走 `/member`） | 收货地址 CRUD（service 模块预留，UI 不实现） |
| 修改密码 / 账号绑定管理（手机/邮箱） | 微信账号绑定（依赖微信登录，V2 同步） |
| 登录设备管理（会话踢出 + 设备移除） | 异地登录二次验证 |
| 推送/隐私/语言/时区/通知设置 | 推送 Token 上报（依赖原生 SDK，仅预留接口） |
| 请求拦截器 + 401 自动刷新 + 路由守卫 | 图形验证码组件（连续登录失败 5 次后弹出，V2 实现） |
| 错误码统一映射 | 单元测试 / E2E 测试（本期开发自测保证） |
| Service 层模块化拆分 | — |

### 1.4 术语表

| 术语 | 含义 |
|---|---|
| accessToken | 短期 JWT 令牌（H5 端 7200s/2h），用于业务接口鉴权 |
| refreshToken | 长期令牌（H5 端 2592000s/30d），用于刷新 accessToken |
| sessionId | 服务端会话 ID，用于会话管理（kick/logout） |
| profile | `users` 表基础资料：username/email/phone/nickname/avatar/gender/birthday |
| profileExtra | `user_profiles` 表扩展资料：bio/signature/regionCode/language/timezone/referralCode/隐私通知设置 |
| bindStatus | 当前用户的多渠道登录方式绑定状态（password/phone/email/wechat） |
| device | `user_devices` 表项，1:N 关联用户，含 deviceId/deviceType/pushToken/pushEnabled |
| session | `user_sessions` 表项，1:N 关联用户，每次登录创建，含 platform/ip/location |

### 1.5 涉及平台与客户端

| 配置 | 值 | 说明 |
|---|---|---|
| OAuth `clientId` | `h5_client` | 与 `database/init.sql` 初始化的 H5 客户端一致 |
| OAuth `clientSecret` | `H5_SECRET` | 集中存放在 `constants/oauth.ts`，便于环境覆盖 |
| 登录平台 `platform` | `h5` | 用于服务端 session 写入与登录日志 |
| 设备类型 `deviceType` | `h5` | 设备注册时使用 |
| accessToken 有效期 | 7200s | 由后端 `oauth_clients` 配置决定 |
| refreshToken 有效期 | 2592000s（30d） | 由后端 `oauth_clients` 配置决定 |

### 2.4 用户类型字段语义混乱（必须修正）

`pages/mine/index.tsx` 第 70 行：`userInfo?.userType === 2 ? '会员用户' : '普通用户'`
`pages/profile/index.tsx` 第 19 行：`userInfo?.userType === 'vip' ? '会员用户' : '普通用户'`
`store/user.ts` 第 76 行注释：`/** 用户类型：1 普通用户 / 2 管理员 / 3 超级管理员 */`

**真实语义**（后端 `users.user_type`）：`1=普通用户`，`2=管理员`，`3=超级管理员`。
**会员判断**应使用 **`/api/member/info` 返回的 `level.code` 与 `paid.isPaid`**，与 `user_type` 完全无关。

本次重构需统一修正：

- 删除前端所有「`userType === 2/'vip'` 判断为会员」的代码
- 「会员用户」徽标显示逻辑改为读取 `useMemberStore.memberInfo.paid.isPaid` 或 `level.level >= 1`
- 删除前端臆造的 `vipExpireAt` 字段引用，改用 `paid.expireAt`

### 3.2 关键架构决策

| 决策 | 选择 | 理由 |
|---|---|---|
| Token 注入位置 | 在 micro-tools 项目内新建 `utils/authRequest.ts`，扩展 shared 的 `request` 拦截器 | shared 层服务于多个子项目，不应耦合 micro-tools 的鉴权策略 |
| Service 模块化 | 拆分为 `service/{auth,user,member,device,common}.ts` | 单文件 200+ 行后续不可维护，按业务域分包 |
| 登录态真源 | `useUserStore.isLoggedIn` 唯一真源 | 避免 token 存在但未登录或登录但 token 失效的双源不一致 |
| 路由守卫位置 | `layouts/index.tsx` 中通过 `useAuthGuard` 拦截 | UmiJS 3 配置式路由不支持 wrappers，layout 是唯一拦截点 |
| 401 刷新策略 | 队列 + 单次刷新 | 多个并发请求同时 401 时，仅发起一次 refresh，其他请求等待 token 后重放 |
| OAuth 凭证管理 | `constants/oauth.ts` 集中存放 | 便于按环境覆盖（开发/预发/生产） |
| Member 模块归属 | 独立 `useMemberStore`，不进 user store | user store 已职责繁重，避免膨胀 |
| Device 模块归属 | 独立 `useDeviceStore` | sessions + devices 数据结构与 user 解耦 |
| 头像上传 | V1 仅支持 URL 输入；V2 接入 OSS | OSS 上传依赖共享层，不在本次范围 |

## 四、M1 登录注册模块

### 4.1 模块目标

提供 H5 移动端友好的多入口登录注册体验：

- **登录入口**：手机号验证码（主推） + 账号密码（兼容老用户，账号支持用户名/邮箱/手机号）
- **注册入口**：手机号一键注册（手机号 + 验证码） + 邮箱注册（用户名 + 邮箱 + 密码）
- **错误处理**：完整对接后端渐进式锁定与验证码限流，给出友好提示
- **跳转策略**：支持 `?redirect=<path>` 回跳，未指定时 `history.goBack()`

### 4.3 四种表单子模式

#### 4.3.1 登录 - 手机号验证码（type=phone）

| 字段 | 校验规则 | 必填 |
|---|---|---|
| phone | `/^1[3-9]\d{9}$/` | ✅ |
| code | 6 位数字 | ✅ |

**操作流程**：

1. 用户输入手机号 → 「发送验证码」按钮亮起
2. 点击发送 → `POST /api/auth/send-code` `{ target: phone, type: 'login', platform: 'h5' }`
3. 成功后按钮进入 60s 倒计时（`useCountdown(60)`），禁用并显示「Xs 后重发」
4. 若返回 429（错误码 100303/100304/100305）→ Toast 显示具体提示，按钮恢复可点击
5. 用户输入验证码 → 点「登录」→ `POST /api/auth/phone-login` `{ phone, code, clientId, clientSecret, platform: 'h5' }`
6. 成功 → 保存 token + user → 若 `isNewUser=true`，Toast「欢迎加入 Super Tools」并跳 `/profile`；否则按 `?redirect` 或 `goBack()`
7. 失败 → 错误码映射后 Toast 显示

#### 4.3.2 登录 - 账号密码（type=password）

| 字段 | 校验规则 | 必填 |
|---|---|---|
| username | 非空（账号/邮箱/手机号通吃，由后端 `Op.or` 匹配） | ✅ |
| password | 非空 | ✅ |
| captcha | 仅在错误码 100601 后显示 | ⚠️ V2 |

**操作流程**：

1. 用户输入 username + password → 点「登录」→ `POST /api/auth/login` `{ username, password, clientId, clientSecret, platform: 'h5' }`
2. 成功 → 同 4.3.1 步骤 6
3. 失败：
   - 401（100101）→ 「账号或密码错误」
   - 423（100602）→ 「账号已被锁定，请 15 分钟后重试」
   - 423（100603）→ 「账号已被永久锁定，请联系管理员」
   - 428（100601）→ 「登录失败次数过多，请输入验证码」（V1 仅提示，V2 显示图形验证码字段）

#### 4.3.3 注册 - 手机号注册（type=phone）

与「登录-手机号验证码」字段完全一致，区别：

- 发送验证码时 `type: 'register'`
- 调用同一个 `POST /api/auth/phone-login` 接口（后端「登录即注册」）
- 用户首次注册返回 `isNewUser=true` → Toast「注册成功，欢迎加入」+ 跳 `/profile?from=register` 引导完善资料

#### 4.3.4 注册 - 邮箱注册（type=email）

| 字段 | 校验规则 | 必填 |
|---|---|---|
| username | 3-50 字符，字母/数字/下划线 | ✅ |
| email | 标准邮箱正则 | ✅ |
| password | ≥ 8 位，含大小写字母 + 数字 | ✅ |
| confirmPassword | === password | ✅ |
| nickname | ≤ 50 字符 | ❌ |

**操作流程**：

1. 用户填写表单 → 点「注册」→ `POST /api/auth/register` `{ username, email, password, nickname?, clientId, platform: 'h5' }`
2. 成功（201）→ Toast「注册成功，请登录」→ 自动切回登录页（`mode=login&type=password`），保留 username 字段
3. 失败：
   - 400（100202/100203）→ 「用户名/邮箱已被注册」
   - 422 → 显示字段级错误

### 4.4 关键交互细节

| 场景 | 行为 |
|---|---|
| 切换 mode（登录↔注册） | 清空所有字段与错误，重置子模式为默认（登录默认 phone，注册默认 phone） |
| 切换 type（子模式） | 清空当前表单字段与错误 |
| 60s 倒计时持久化 | 倒计时结束前若用户离开页面又返回，按钮应继续显示剩余时间（state 存 zustand 全局状态） |
| 离开页面 | 倒计时不清除，下次进入页面继续；表单字段不持久化 |
| `redirect` 参数 | 解析 `useLocation().query.redirect`，登录成功后 `history.replace(redirect)`；防钓鱼仅允许站内路径（`/` 开头且不含 `://`） |
| 协议勾选 | 默认勾选；若未勾选点击主操作按钮 → Toast「请先阅读并同意《用户协议》」 |

## 七、M4 鉴权基建模块

### 7.1 请求层（`utils/authRequest.ts`）

#### 7.1.1 设计目标

- 自动为业务接口注入 `Authorization: Bearer <token>` 头
- 401 时自动调用 refreshToken 并重放原请求
- 多个并发 401 请求只触发一次 refresh，其他排队等待
- refresh 失败 → 清空登录态 → 跳转 `/login?redirect=<current>`
- 公开接口（白名单）跳过 token 注入

#### 7.1.2 白名单（详见 `constants/oauth.ts` 第 9.2 节）

#### 7.1.3 实现伪代码

```typescript
// utils/authRequest.ts
import request from '@/utils/request';
import { history } from 'umi';
import { isWhitelisted, TOKEN_STORAGE_KEY } from '../constants/oauth';
import { useUserStore } from '../store/user';

let isRefreshing = false;
let pendingQueue: Array<{
  resolve: (token: string) => void;
  reject: (err: Error) => void;
}> = [];

const flushQueue = (token: string | null, error?: Error) => {
  pendingQueue.forEach(({ resolve, reject }) => {
    if (token) resolve(token);
    else reject(error || new Error('Token refresh failed'));
  });
  pendingQueue = [];
};

const getAccessTokenFromStorage = (): string | null => {
  try {
    const raw = localStorage.getItem(TOKEN_STORAGE_KEY);
    if (!raw) return null;
    return JSON.parse(raw).accessToken || null;
  } catch { return null; }
};

// 请求拦截：注入 Token
request.interceptors.request.use((url, options) => {
  if (!isWhitelisted(url)) {
    const token = getAccessTokenFromStorage();
    if (token) {
      options.headers = {
        ...(options.headers || {}),
        Authorization: `Bearer ${token}`,
      };
    }
  }
  return { url, options };
});

// 响应拦截：401 自动刷新
request.interceptors.response.use(async (response, options: any) => {
  if (response.status !== 401 || isWhitelisted(response.url) || options.__isRetry) {
    return response;
  }

  if (isRefreshing) {
    return new Promise((resolve, reject) => {
      pendingQueue.push({
        resolve: (newToken) => {
          options.headers = { ...options.headers, Authorization: `Bearer ${newToken}` };
          resolve(request(response.url, { ...options, __isRetry: true }));
        },
        reject,
      });
    });
  }

  isRefreshing = true;
  try {
    const ok = await useUserStore.getState().refreshToken();
    if (!ok) throw new Error('refresh failed');
    const newToken = getAccessTokenFromStorage()!;
    flushQueue(newToken);
    options.headers = { ...options.headers, Authorization: `Bearer ${newToken}` };
    return request(response.url, { ...options, __isRetry: true });
  } catch (err: any) {
    flushQueue(null, err);
    useUserStore.getState().reset();
    history.replace(`/login?redirect=${encodeURIComponent(history.location.pathname)}`);
    return response;
  } finally {
    isRefreshing = false;
  }
});
```

// hooks/useAuthGuard.ts
import { useEffect } from 'react';
import { history } from 'umi';
import { useUserStore } from '../store';
import { PROTECTED_PATHS } from '../constants/oauth';

export const useAuthGuard = (pathname: string, authChecked: boolean) => {
  const isLoggedIn = useUserStore(s => s.isLoggedIn);

  useEffect(() => {
    if (!authChecked) return;
    const needAuth = PROTECTED_PATHS.some(p =>
      pathname === p || pathname.startsWith(`${p}/`),
    );
    if (needAuth && !isLoggedIn) {

    }
  }, [authChecked, isLoggedIn, pathname]);
};

**初始化流程（initAuth）**：

```
1. 读取 localStorage token
2. 若无 → return（未登录态）
3. 若过期：

   3b. 失败 → clearToken + 维持未登录态 → return
4. 设置 isLoggedIn = true
5. 并行 fetchProfile() + fetchProfileExtra() + fetchBindStatus()
   （任一失败不影响登录态，只 console.warn）
6. 触发 useDeviceStore.registerCurrentDevice() upsert 当前设备
7. 触发 useMemberStore.fetchMemberInfo() 拉取会员信息
```

| HTTP | 前端映射文案 |
|---|---|

| 404 | 资源不存在 |

#### B.1 命名约定

- 常量文件：单数 + 名词。如 `oauth.ts`、`errorMap.ts`

#### B.2 错误处理范式

```typescript
// Service 层：抛出 error，不做提示
export const loginByPhone = async (params) => {
  return request.post('/api/auth/phone-login', { data: params });
};

// Store 层：捕获错误 → 映射 → 写入 state
loginByPhone: async (params) => {
  set(s => { s.loading = true; s.error = null; });
  try {
    const res = await service.auth.loginByPhone({ ...params, clientId, clientSecret, platform });
    if (res?.code === 200) {
      // ... 成功处理
      return { success: true, message: '登录成功', isNewUser: res.data.isNewUser };
    }
    const msg = mapErrorCode(res?.code, res?.message);
    set(s => { s.loading = false; s.error = msg; });
    return { success: false, message: msg };
  } catch (e: any) {
    const code = e?.data?.code || e?.response?.status;
    const msg = mapErrorCode(code, e?.data?.message || e?.message || '登录失败');
    set(s => { s.loading = false; s.error = msg; });
    return { success: false, message: msg };
  }
}

// Page 层：仅消费 ActionResult，按需 Toast
const handleSubmit = async () => {
  const result = await loginByPhone({ phone, code });
  if (result.success) {
    Toast.success(result.message);
    history.replace(redirect || '/');
  } else {
    Toast.error(result.message);
  }
};
```
