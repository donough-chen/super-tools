## 一、文件命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| 组件目录 | PascalCase | `AppHeader/`、`AppModal/` |
| 页面目录 | kebab-case | `home/`、`search/` |
| Store 文件 | camelCase | `global.ts`、`home.ts` |
| Hook 文件 | camelCase (use 前缀) | `useSwipe.ts` |
| 样式文件 | 与组件/页面同名 | `AppHeader.less`、`index.less` |
| 常量文件 | camelCase | `index.ts` |
| 类型定义 | 就近原则 | 定义在使用处的 Store/组件内部 |

## 二、样式规范

### 2.1 CSS 类名命名（BEM 变体）

```
.page-{页面名}__{元素名}
.page-{页面名}__{元素名}--{修饰符}
```

示例：

```less
.page-home {}
.page-home__content {}
.page-home__tool-list {}
.page-home__tool-list--grid {}
.page-home__tool-item {}
```

组件使用简化前缀：

```less
.app-header {}
.app-header__title {}
.app-header__btn--search {}
```

### 2.2 使用 CSS 变量

- **所有颜色、间距、字号、圆角、高度必须引用 CSS 变量**，不要硬编码
- 在 `.less` 文件开头导入变量文件：

```less
@import '~@/assets/variables.less';
```

### 2.3 尺寸单位

- 使用 `px` 编写，`postcss-pxtorem` 自动转换为 `rem`
- 设计稿宽度 750px，直接量取设计稿标注值
- 例外：`1px` 边框线不转换（pxtorem 配置 `minPixelValue: 2`）

### 2.4 毛玻璃效果

统一使用 CSS 变量：

```less
background: var(--glass-bg);
backdrop-filter: blur(var(--glass-blur));
-webkit-backdrop-filter: blur(var(--glass-blur));
border: var(--glass-border);
```

## 三、组件开发规范

### 3.1 组件结构

```
components/
└── MyComponent/
    ├── index.tsx      # 组件实现 + 类型导出
    └── MyComponent.less
```

### 3.2 组件编写规范

```tsx
/**
 * 组件名称 - 简要说明
 */
import React, { FC } from 'react';
import classnames from 'classnames';
import './MyComponent.less';

// 1. 导出接口类型
export interface MyComponentProps {
  /** 属性说明 */
  prop: string;
}

// 2. 组件实现
const MyComponent: FC<MyComponentProps> = ({ prop }) => {
  return (
    <div className="my-component">
      {/* ... */}
    </div>
  );
};

// 3. 默认导出
export default MyComponent;
```

### 3.3 组件导出

从 `components/index.ts` 统一导出：

```typescript
export { default as MyComponent } from './MyComponent';
export type { MyComponentProps } from './MyComponent';
```

## 四、状态管理规范

### 4.1 Store 文件结构

```typescript
// 1. 导入
import { create } from 'zustand';
import { immer } from 'zustand/middleware/immer';

// 2. State 接口
interface XxxState { /* ... */ }

// 3. Actions 接口
interface XxxActions { /* ... */ }

// 4. 初始状态
const initialState: XxxState = { /* ... */ };

// 5. 创建 Store
export const useXxxStore = create<XxxState & XxxActions>()(
  immer(set => ({
    ...initialState,
    // actions...
  })),
);
```

### 4.2 immer 使用注意

```typescript
// ✅ 正确：直接修改 state
set(state => {
  state.loading = true;
  state.error = null;
});

// ❌ 错误：返回新对象（immer 模式下不需要）
set(state => ({
  ...state,
  loading: true,
}));

// ✅ 重置状态的特殊写法
set(() => ({ ...initialState }));
```

## 五、路由规范

### 5.1 三环境路由一致性

路由声明需要在三个配置文件中**保持完全一致**：

- `.umirc.dev.ts` — 开发环境
- `.umirc.preview.ts` — 预发布环境
- `.umirc.prod.ts` — 生产环境

### 5.2 路由 URL 前缀

| 环境 | base | publicPath |
|------|------|------------|
| 开发 | `/fe/h5/micro-tools/` | `/fe/h5/micro-tools/` |
| 预发布 | `/fepreview/h5/micro-tools/` | `/fepreview/h5/micro-tools/` |
| 生产 | `/fe/h5/micro-tools/` | `https://your-cdn.com/fe/h5/micro-tools/` |

### 5.3 路由守卫

Layout 层（`layouts/index.tsx`）提供以下守卫功能：

- 设置页面标题（`document.title`）
- 登录态检测（Milo / AppSdk）
- vConsole 注入（非生产环境）
- 端外跳转引导下载

## 六、性能优化指南

### 6.1 路由级代码分割

已通过 `dynamicImport` 开启，每个路由独立 chunk，无需额外配置。

### 6.2 KeepAlive 缓存

一级页面已启用 KeepAlive，切换时不重新挂载。注意事项：

- 需要刷新数据时，使用 `useKeepAliveActivation` 监听激活事件
- 避免在 `useEffect(() => {...}, [])` 中做一次性初始化（KeepAlive 页面只执行一次）

### 6.3 IntersectionObserver

首页搜索框使用 `IntersectionObserver` 检测可见性，避免 `scroll` 事件监听的性能开销。

### 6.4 图片懒加载

长列表中的图片建议使用 `loading="lazy"` 属性或 `IntersectionObserver` 实现懒加载。

### 6.5 Banner 滚动优化

使用 `requestAnimationFrame` 节流原生 scroll 事件回调，避免高频重渲染。

## 八、常见问题 FAQ

### Q1：样式中的 px 值是设计稿上的值还是实际像素？

**A：直接使用 750px 设计稿上的标注值。** `postcss-pxtorem` 会自动将 px 转换为 rem。例如设计稿标注 `32px`，代码中写 `32px`，构建后自动变为 `1.6rem`。

### Q2：如何引用 shared 层的工具/组件？

**A：通过别名引用：**

```typescript
import { request } from '@/utils';      // → packages/shared/utils
import { useXxx } from '@/hooks';       // → packages/shared/hooks
import { Button } from '@/components';  // → packages/shared/components
```

### Q3：Mock 数据和真实接口如何切换？

**A：** Mock 数据在 `mock/index.ts` 中定义。开发环境下 Mock 优先级高于代理。如需使用真实接口，注释掉 `mock/index.ts` 中对应的 Mock 定义。

### Q4：新增一个一级页面需要改几处？

**A：需要修改以下位置：**

1. `pages/` — 创建页面组件
2. `.umirc.dev.ts` / `.umirc.preview.ts` / `.umirc.prod.ts` — 注册路由（3 个文件）
3. `constants/index.ts` — 添加 `TAB_BAR_ITEMS` 配置
4. `components/KeepAlive/CacheRoute.tsx` — 添加到 `CACHE_ROUTES`
5. （可选）`store/` — 创建对应 Store

### Q5：为什么组件样式没生效？

**A：检查以下几点：**

1. 是否在组件中 import 了 `.less` 文件
2. CSS 类名是否正确（注意 BEM 格式）
3. 是否使用了未定义的 CSS 变量
4. 样式文件中是否 `@import '~@/assets/variables.less'`

### Q6：如何实现页面间数据传递？

**A：推荐以下方式（优先级从高到低）：**

1. **Zustand Store** — 跨页面共享状态（推荐）
2. **URL 参数** — 通过 `?key=value` 传递简单数据
3. **localStorage** — 持久化数据

不推荐使用 `history.state` 或 `React Context`。

### Q7：KeepAlive 缓存的页面如何在重新激活时刷新数据？

**A：** 使用 `useKeepAliveActivation` Hook：

```tsx
import { useKeepAliveActivation } from '../../components';

useKeepAliveActivation({
  onActivated: () => {
    // 页面重新激活时执行
    fetchList();
  },
});
```

### Q8：主题色修改后为什么部分样式没变？

**A：** 确保使用 CSS 变量 `var(--primary-color)` 引用主题色，不要硬编码颜色值。`setThemeColor` 只更新 CSS 变量，硬编码的颜色不会跟随变化。

### Q9：F5 刷新页面后登录态丢失，需要重新登录？

**A：** Zustand Store 在页面刷新时会重置为初始状态（`isLoggedIn: false`），而 Token 持久化在 localStorage 中。因此必须在应用启动时调用 `useUserStore` 的 `initAuth()` 方法从 localStorage 恢复登录态。

**正确做法：** 在 `layouts/index.tsx`（Layout 入口）中通过 `useEffect` 调用 `initAuth()`：

```tsx
import { useUserStore } from '../store';

export default ({ children, location, ...restProps }: any) => {
  const initAuth = useUserStore(state => state.initAuth);

  useEffect(() => {
    initAuth();
  }, []);

  return (
    <SharedLayout location={location} {...restProps}>
      {/* ... */}
    </SharedLayout>
  );
};
```

**关键点：** Layout 是所有页面的公共入口，在此处调用可保证任意页面刷新都能恢复登录态。

### Q10：React Hook 必须在函数组件内部调用

**A：** `useHistory()`、`useState()` 等 React Hook 只能在函数组件的函数体内部调用，不能放在模块顶层。违反此规则会导致 `Invalid hook call` 错误，页面无法渲染（一直显示"加载中"）。

```tsx
// ❌ 错误：模块顶层调用 Hook
const history = useHistory();
const MyPage: React.FC = () => { /* ... */ };

// ✅ 正确：在函数组件内部调用 Hook
const MyPage: React.FC = () => {
  const history = useHistory();
  /* ... */
};
```

### Q11：长按手势与 onClick 冲突如何处理？

**症状**：长按触发操作浮层后，松手瞬间还会误触发 `onClick` 跳转到工具详情页。

**原因**：iOS Safari 在 `touchend` 之后会合成一次 `click` 事件；React 的 `onClick` 会再次响应。

**解决**：统一使用 `hooks/useLongPress`（默认 `suppressClickAfter: true`），它会：

1. 在长按触发时记录 `triggeredRef`
2. 在 `touchend` 阶段调用 `e.preventDefault()` 阻止合成 click
3. 如果合成 click 仍然到达，在 `onClick` 包装器中读取 `triggeredRef` 再次拦截

```tsx
const bind = useLongPress({
  onLongPress: () => showActionPopup(),
  onClick: () => navigateTo(tool.path),
});
<div {...bind}>{/* 不要额外写 onClick！统一走 useLongPress 返回的 handlers */}</div>
```

### Q12：ToolActionPopup 显示不全、被遮挡或超出屏幕？

**v2 已通过 Portal + 智能定位解决大部分问题：**

- 浮层 DOM 挂载到 `document.body`，不再受父容器 `overflow: hidden` 裁切
- 根据 `targetRef.getBoundingClientRect()` 自动选择弹出方向：右侧空间不足时自动左对齐、下方空间不足时自动上弹

**若仍出现异常，按以下顺序排查：**

1. 是否正确传递 `targetRef` 到目标 item 的 DOM（而非普通变量或 props 透传的非 ref 对象）
2. item 是否处于 `transform` 祖先下（某些浏览器会影响 Portal 元素的 `position: fixed`）——此时改为让 Portal 挂到页面根层即可
3. 是否出现多个浮层同时显示：请用 `popupKey === item.key` 作为 `visible`，保证同一时间仅一个

### Q13：长按拖拽排序后，item 自动"弹回"到原位置？

**典型症状**：长按后拖到目标位置松手，能看到 item 吸附到新位置，但下一个渲染周期立刻跳回。

**根因**：`useEffect(() => { if (dragIndex === null) setLocalList([...storeList]) }, [storeList, dragIndex])` 这种写法——`endDrag()` 将 `dragIndex` 设为 null 会触发此 effect，用未变更的 `storeList` 覆盖刚排序好的 `localList`。

**正确做法**：使用 `initializedRef` 标记，只在"首次挂载"或"集合内容变化（增删）"时同步 `localList`；拖拽结束后**永远不要**用 `storeList` 覆盖本地顺序。

```tsx
const initializedRef = useRef(false);

useEffect(() => {
  if (storeList.length === 0) return;
  if (!initializedRef.current) {
    setLocalList([...storeList]);
    initializedRef.current = true;
    return;
  }
  // 仅当条目集合发生增删时才同步；纯顺序差异保持本地编辑
  const storeCodes = storeList.map(f => f.toolCode).sort().join(',');
  const localCodes = localList.map(f => f.toolCode).sort().join(',');
  if (storeCodes !== localCodes) setLocalList([...storeList]);
}, [storeList]);
```

另外拖拽位移的单位高度不要硬编码（例如 `ITEM_HEIGHT = 72`），因为 less 中的 `gap` 会导致 item 实际中心距 ≠ offsetHeight。应在挂载后通过 DOM 实测两相邻 item 的 `getBoundingClientRect().top` 差值。
