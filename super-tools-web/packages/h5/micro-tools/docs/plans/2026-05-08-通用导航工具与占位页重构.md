# 2026-05-08 通用导航工具与占位页重构

## 背景

原 `pc/tool-box/utils/navigator.ts` 仅服务于 PC 端；`micro-tools` 各页面直接使用 `umi` 的 `useHistory()` / `history.push/replace/goBack`，存在以下问题：

- 跳转语义分散（`history.push` / `window.open` / `useHistory` 混用），无统一出口
- 未来新增小程序 / 打点埋点等能力时改造面非常大
- 多包无法复用 PC 端已有的 `navigate()` 抽象
- 部分二级路由页面功能尚未开发，用户进入后为空白页，体验较差

本次重构将 `navigator.ts` 迁移到 `packages/shared/utils`，两端共用；同时新增通用"功能开发中"占位页组件 `UnderConstruction`，并把 `micro-tools` 中所有 `history` 调用替换为 navigator 工具函数。

## 目标

1. `navigator` 成为 super-tools 前端全局唯一的跳转入口
2. 导航函数统一语义，便于后续扩展（重定向、打点、拦截确认等）
3. 提供统一占位页，覆盖"二级页面未上线"场景，视觉适配移动端 + 桌面端 + 暗色模式
4. 不破坏历史调用路径：`resolveIcon` 仍兼容 `/assets/imgs/xxx.svg`

## 方案

### 1. navigator 迁移与增强

- 源文件：`super-tools-web/packages/pc/tool-box/utils/navigator.ts`
- 目标位置：`super-tools-web/packages/shared/utils/navigator.ts`
- 新增 API：
  - `navigateReplace(path, state?)` — 等价于 `history.replace`
  - `getCurrentPathname()` — 读取当前路径（供非组件代码使用）
  - `getCurrentLocation()` — 返回含 `pathname` / `search` / `query` / `state` 的对象
- 导出 re-export：统一从 `packages/shared/utils` 暴露

### 2. 通用占位页 UnderConstruction

- 目录：`super-tools-web/packages/shared/components/UnderConstruction/`
- 组件 Props：
  - `title` / `description` / `backText`
  - `onBack`：默认 `navigateBack()`
  - `showHome` / `homePath` / `homeText`：可选"返回首页"按钮
- 样式要点：
  - 双齿轮 + 路障锥插画，齿轮 `@keyframes st-uc-spin` 旋转
  - `@media (min-width: 768px)`：两按钮横向排列、字号放大
  - `@media (prefers-color-scheme: dark)`：暗色模式

### 3. micro-tools 全量替换 history 调用

映射规则（本次固化）：

| 旧调用 | 新调用 |
| --- | --- |
| `useHistory()` 取 history | 直接 import `navigateTo/...` |
| `history.push(path)` | `navigateTo(path)` |
| `history.replace(path)` | `navigateReplace(path)` |
| `history.goBack()` | `navigateBack()` |
| `history.go(-n)` | `navigateBack(n)` |
| `window.open(url, '_blank')` | `openUrl(url)` |

## 补充：路由拦截能力（2026-05-08 晚补）

### 背景

navigator + UnderConstruction 已就绪，但缺少「跳转前的路由预检」：当后端下发的 `tool.path`（或任意动态路径）尚未在前端注册路由时，直接 `navigateTo` 会进入空白页。

### 方案

1. **新增 `constants/routes.ts`**：集中维护 `KNOWN_ROUTES` 白名单 + `KNOWN_ROUTE_PREFIXES` 前缀白名单 + `isKnownRoute()` 判断函数，`FALLBACK_ROUTE = '/404'`。
2. **新增 `pages/404.tsx`**：UmiJS 约定兜底页，直接渲染 `UnderConstruction`（`title="功能开发中"`、`showHome`）。当用户直接访问不存在的 URL 时由 umi 自动渲染。
3. **新增 `utils/safeNavigate.ts`**：封装带白名单预检的 `safeNavigate` / `safeNavigateReplace`。规则：
   - 外链（http/https）→ `openUrl` 新窗口
   - 已知路由 → 正常跳转
   - 未知路由 → 跳 `/404`，并把原目标路径写入 `history.state.from`（便于埋点）
4. **改造 `useToolClick`**：3 处 `navigateTo(tool.path)` 全部替换为 `safeNavigate(tool.path)`（登录/会员/提示等应用内固定路由仍用 `navigateTo`）。
5. **改造 `pages/favorites/index.tsx`** 与 **`pages/mine/index.tsx`**：直接跳转 `tool.url` / 菜单 `item.path` 的入口也改为 `safeNavigate`。

### 维护约定

- 新增页面时需在 `constants/routes.ts` 的 `KNOWN_ROUTES` 中登记；未登记的路径将被拦截到 /404。
- 若某类工具走动态路由（例如 `/tools/:code`），只需在 `KNOWN_ROUTE_PREFIXES` 追加 `/tools/` 前缀即可。
- `navigator.ts` 保持 shared 包的"纯跳转"语义，不内嵌业务白名单；白名单逻辑局限在 micro-tools 侧的 `safeNavigate`。

### 涉及文件

- 新增：`constants/routes.ts`、`pages/404.tsx`、`utils/safeNavigate.ts`
- 修改：`hooks/useToolClick.ts`、`pages/favorites/index.tsx`、`pages/mine/index.tsx`

## 补充 2：路由白名单单一事实源（2026-05-08 再补）

### 背景

上一版白名单 (`constants/routes.ts`) 与 `.umirc.*.ts` 里的 `routes` 两份数据需要手动同步，新增页面要改两处，容易漏。

### 方案

抽离 **`routes.config.ts`** 作为路由的单一事实源（SSOT）：

1. **新增 `routes.config.ts`**：
   - 导出 `PAGE_ROUTES`（业务页面扁平数组）、`UMI_ROUTES`（带 layout 包裹的完整结构，供 umi 使用）、`ALL_ROUTE_PATHS`（递归扁平化的路径白名单，供运行时使用）。
   - 纯数据 + 纯类型，不 import 任何 Node/浏览器专属 API，两端均可安全引用。
2. **改造 `.umirc.dev.ts` / `.umirc.preview.ts` / `.umirc.prod.ts`**：
   - `routes` 字段直接 `import { UMI_ROUTES } from './routes.config'`
   - 各自保留自身的 `base / publicPath / proxy` 等环境差异
3. **改造 `constants/routes.ts`**：
   - `KNOWN_ROUTES` 由 `ALL_ROUTE_PATHS` 派生，不再手写业务路径
   - 保留 `EXTRA_ROUTE_PREFIXES`（兼容别名 `KNOWN_ROUTE_PREFIXES`）供动态路由前缀登记，它们通常不对应物理 page 文件

### 维护约定（更新）

- **新增 / 下线页面只改 `routes.config.ts`**；`.umirc` 与白名单会自动同步
- **不落在 `pages/` 下的动态路由**（例如 `/tools/:code`）在 `EXTRA_ROUTE_PREFIXES` 登记前缀
- 不得在 `routes.config.ts` 内 import `path`/`fs` 等 Node API，否则会污染浏览器 bundle

### 涉及文件

- 新增：`routes.config.ts`
- 修改：`.umirc.dev.ts`、`.umirc.preview.ts`、`.umirc.prod.ts`、`constants/routes.ts`

## 补充 3：AppTabBar active 状态由路由派生（2026-05-08 三补）

### 现象

从「特色页」点击工具卡进入未注册路由 → 被 `safeNavigate` 拦截到 `/404` → 点击「返回首页」跳到 `/` 后，AppTabBar 仍高亮「特色」tab，未切到「首页」。

### 根因

`AppTabBar` 的 `activeKey` 由 `useGlobalStore().activeTabBarKey` 驱动，而该状态**只在用户点击 tab 时**通过 `setActiveTabBarKey` 更新。其他场景（直接访问 URL、`safeNavigate('/')`、404 内"返回首页"等）都不会同步它，于是与 `location.pathname` 脱节。

### 方案

把 `activeKey` 由「显式 store 状态」改为「**根据 location.pathname 派生**」（SSOT 即路由本身）。

1. **改造 `components/AppTabBar/index.tsx`**：
   - 内部 `useLocation()` + `deriveActiveKey(pathname, items)` 自动算出 active key
   - `activeKey` 改为可选，传入即覆盖派生（保留特殊场景能力）
   - `onChange` 也改为可选，未传时默认 `safeNavigate('/' or '/{key}')`
   - 派生规则：`'/' → 'home'` → 完全匹配 `'/{key}'` → 前缀匹配 `'/{key}/...'`
2. **简化 5 个 tab 页**（home/featured/favorites/sites/mine）：
   - 不再传 `activeKey`/`onChange`，仅 `<AppTabBar mode={tabBarMode} items={TAB_BAR_ITEMS} />`
   - 不再从 `useGlobalStore` 解构 `activeTabBarKey` / `setActiveTabBarKey`
3. **store 不动**：`global.ts` 中 `activeTabBarKey` / `setActiveTabBarKey` 暂保留导出兼容，留待后续清理。

### 涉及文件

- 修改：
  - `components/AppTabBar/index.tsx`
  - `pages/home/index.tsx`、`pages/featured/index.tsx`、`pages/favorites/index.tsx`、`pages/sites/index.tsx`、`pages/mine/index.tsx`
