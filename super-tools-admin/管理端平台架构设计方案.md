# 通用管理端平台架构模板文档

**版本：** v1.0.0 | **适用场景：** 中后台管理系统 | **技术基座：** UmiJS + Ant Design Pro

---

## 一、技术栈选型

### 1.1 核心技术栈

| 类别      | 推荐技术                      | 版本建议    | 说明                                                  |
| --------- | ----------------------------- | ----------- | ----------------------------------------------------- |
| 应用框架  | **UmiJS**                     | 3.x / 4.x   | 企业级前端框架，内置路由、构建、插件体系              |
| UI 框架   | **Ant Design Pro**            | 5.x         | 中后台解决方案，提供 ProLayout、ProTable 等高阶组件   |
| 状态管理  | **DVA**                       | 2.x         | 基于 Redux + Redux-Saga，UmiJS 内置集成，支持 `immer` |
| 视图层    | **React（函数组件 + Hooks）** | 17.x / 18.x | 使用 `useSelector`、`useDispatch`、`useCallback` 等   |
| 语言      | **TypeScript**                | 4.x+        | 全量 TS，提供完整类型安全保障                         |
| 样式      | **Less / CSS Modules**        | —           | 模块化样式，配合 Ant Design 主题变量                  |
| HTTP 请求 | **umi-request / axios**       | —           | 支持中间件拦截器，统一请求封装                        |

> **语言选型说明：** 新项目建议直接采用 TypeScript 全量接入；存量 JS 项目可按模块逐步迁移，优先覆盖 `models/`、`utils/`、`components/` 目录。

### 1.2 可选扩展依赖

根据业务需要按需引入，避免不必要的包体积膨胀。

### 1.4 后端接口层约定

本模板定位为**纯前端工程**，后端服务独立部署。前后端通过 HTTP 接口交互，建议遵循以下约定：

| 服务类型        | 说明                                  | 示例域名规范                                 |
| --------------- | ------------------------------------- | -------------------------------------------- |
| 主业务服务      | 核心业务接口（菜单、权限、数据 CRUD） | `api-stag.example.com` / `api.example.com`   |
| 用户身份服务    | 登录鉴权、Session 同步                | `auth-stag.example.com` / `auth.example.com` |
| 第三方/游戏服务 | 外部业务数据接口                      | 按实际业务配置                               |

> **安全建议：** 后端服务域名不应硬编码在前端源码中，应通过构建时 `define` 注入环境变量，详见 [§4.3 安全性规范](#43-安全性规范)。

### 2.2 分层架构说明

```
┌─────────────────────────────────────────────────────┐
│                   路由层 (Router)                     │
│         按环境/模块拆分，支持动态路由聚合              │
├─────────────────────────────────────────────────────┤
│                   布局层 (Layouts)                    │
│    SecurityLayout → AuthLayout → BasicLayout         │
├─────────────────────────────────────────────────────┤
│                   权限层 (Auth)                       │
│    登录校验 → 菜单级权限 → 路由级权限 → 按钮级权限    │
├─────────────────────────────────────────────────────┤
│                   页面层 (Pages)                      │
│         各业务模块页面，按功能域划分目录               │
├─────────────────────────────────────────────────────┤
│                   组件层 (Components)                 │
│    AuthButton | AuthWrapper | Editor | 业务组件 …    │
├─────────────────────────────────────────────────────┤
│                   数据层 (DVA Models)                 │
│         global | user | setting | 页面级 model       │
├─────────────────────────────────────────────────────┤
│                   工具层 (Utils)                      │
│    request.js | utils.ts | authority.ts | 业务工具   │
└─────────────────────────────────────────────────────┘
```

**各层职责说明：**

| 层级   | 职责                                       | 关键原则                                 |
| ------ | ------------------------------------------ | ---------------------------------------- |
| 路由层 | 定义页面访问路径，配置路由守卫             | 按模块拆分，显式聚合，避免动态文件扫描   |
| 布局层 | 提供页面骨架（菜单、Header、Tabs）         | 布局与业务解耦，支持多套布局切换         |
| 权限层 | 控制访问资格（登录态、菜单权限、按钮权限） | 权限校验前置，避免内容闪现               |
| 页面层 | 承载具体业务逻辑与视图                     | 页面内聚，跨页面逻辑下沉至组件层或数据层 |
| 组件层 | 提供可复用 UI 组件                         | 无业务状态依赖，通过 props 驱动          |
| 数据层 | 管理应用状态，处理异步副作用               | Effect 负责异步，Reducer 负责纯同步更新  |
| 工具层 | 提供无状态纯函数工具                       | 不依赖 React 上下文，可独立测试          |

### 2.3 数据流设计

```
用户操作
```

**Model 标准结构模板：**

```typescript
// src/models/example.ts
import { Effect, ImmerReducer, Subscription } from 'umi';

export interface ExampleState {
  list: ExampleItem[];
  total: number;
  loading: boolean;
}

export interface ExampleModelType {
  namespace: 'example';
  state: ExampleState;
  effects: {
    fetchList: Effect;
    createItem: Effect;
    updateItem: Effect;
    deleteItem: Effect;
  };
  reducers: {
    setList: ImmerReducer<ExampleState>;
    setLoading: ImmerReducer<ExampleState>;
  };
  subscriptions: {
    setup: Subscription;
  };
}

const ExampleModel: ExampleModelType = {
  namespace: 'example',

  state: {
    list: [],
    total: 0,
    loading: false,
  },

  effects: {
    *fetchList({ payload }, { call, put }) {
      yield put({ type: 'setLoading', payload: true });
      try {
        const { data } = yield call(fetchListApi, payload);
        yield put({ type: 'setList', payload: data });
      } finally {
        yield put({ type: 'setLoading', payload: false });
      }
    },
  },

  reducers: {
    setList(state, { payload }) {
      state.list = payload.list;
      state.total = payload.total;
    },
    setLoading(state, { payload }) {
      state.loading = payload;
    },
  },

  subscriptions: {
    setup({ history, dispatch }) {
      // 路由监听，按需使用
    },
  },
};

export default ExampleModel;
```

### 2.4 HTTP 请求封装规范

**统一请求实例**（`src/utils/request.ts`）：

```typescript
import { extend, ResponseError } from 'umi-request';
import { notification } from 'antd';

// 业务状态码枚举
enum BizCode {
  SUCCESS = 0,
  UNAUTHORIZED = -1002,
  BIZ_ERROR = 1,
}

// 错误处理器
const errorHandler = (error: ResponseError) => {
  const { response } = error;
  if (response?.status) {
    notification.error({
      message: `请求错误 ${response.status}`,
      description: error.message,
    });
  } else {
    notification.error({ message: '网络异常，请检查网络连接' });
  }
  throw error;
};

// 创建请求实例
const request = extend({
  credentials: 'include', // 携带 Cookie
  errorHandler,
});

// 响应拦截器：统一处理业务状态码
request.interceptors.response.use(async (response) => {
  const data = await response.clone().json();

  switch (data?.code) {
    case BizCode.SUCCESS:
      return data.data;

    case BizCode.UNAUTHORIZED:
      // 跳转登录页，避免循环重定向
      if (window.location.pathname !== '/login') {
        window.location.href = '/login';
      }
      break;

    case BizCode.BIZ_ERROR:
      // 业务错误，返回给调用方处理
      return Promise.resolve({ code: data.code, msg: data.msg });

    default:
      notification.error({ message: data?.msg || '服务异常，请稍后重试' });
      return Promise.reject(new Error(data?.msg));
  }

  return response;
});

export default request;
```

**接口层规范**（`src/services/example.ts`）：

```typescript
import request from '@/utils/request';

// 接口定义与业务逻辑分离，services 层只负责接口调用
export const fetchListApi = (params: ListParams) =>
  request.get('/api/example/list', { params });

export const createItemApi = (data: CreateItemPayload) =>
  request.post('/api/example/create', { data });

export const updateItemApi = (data: UpdateItemPayload) =>
  request.put('/api/example/update', { data });

export const deleteItemApi = (id: number) =>
  request.delete(`/api/example/${id}`);
```

### 2.5 多环境构建策略

通过 `BUILD_ENV` 环境变量控制构建产物与路由前缀：

| 变量        | 值            | 路由前缀 | 输出目录     | 适用场景 |
| ----------- | ------------- | -------- | ------------ | -------- |
| `BUILD_ENV` | `development` | `/`      | `dist/dev/`  | 本地开发 |
| `BUILD_ENV` | `test`        | `/test`  | `dist/test/` | 测试环境 |
| `BUILD_ENV` | `production`  | `/pro`   | `dist/pro/`  | 生产环境 |

### 2.6 多页签 + iframe 混合架构（可选）

适用于需要同时承载多个子系统的管理平台，采用 **Tabs + iframe 混合嵌入**模式：

```
主框架 (main.tsx)
├── 侧边菜单 (ProLayout)
├── 顶部工具栏 (业务选择器 / 用户信息 / 公告)
└── 多页签容器 (Tabs)
    ├── Tab 1: 首页 (React 原生页面)
    ├── Tab 2: 子系统 A (iframe 嵌入)
    ├── Tab 3: 子系统 B (iframe 嵌入)
    └── Tab N: ...（上限建议 ≤ 15）
```

**关键设计决策：**

| 决策点          | 推荐方案                     | 说明                                        |
| --------------- | ---------------------------- | ------------------------------------------- |
| Tab 上限        | ≤ 15 个                      | 超出时提示用户关闭旧 Tab                    |
| iframe 生命周期 | LRU 缓存策略                 | 超出上限时销毁最久未访问的 iframe，释放内存 |
| 跨域通信        | `postMessage`                | 禁止通过 URL 参数传递敏感信息               |
| iframe 安全     | 设置 `sandbox` 属性          | 按需开放权限，最小化攻击面                  |
| 未来演进        | 评估 `qiankun` / `micro-app` | 解决 iframe 性能、通信、样式隔离问题        |

### 3.2 核心文件职责说明

| 文件/目录                        | 职责                                                       | 关键约束                 |
| -------------------------------- | ---------------------------------------------------------- | ------------------------ |

```
│   ├── components/          # 页面私有组件（不对外暴露）
│   │   ├── EditModal.tsx    # 编辑弹窗
│   │   └── SearchForm.tsx   # 搜索表单
│   ├── index.tsx            # 页面入口（视图层）
│   ├── index.less           # 页面样式
│   └── model.ts             # 页面级 DVA model（仅本页面使用）
```

**约定规则：**

- `components/` 内的组件**不得**被其他页面直接引用，跨页面复用须提升至 `src/components/`
- 每个页面维护**独立的** `model.ts`，禁止多页面共用同一 model 文件
- 页面入口文件只负责**组合**，复杂逻辑下沉至 `components/` 或 `model.ts`

## 四、权限体系设计

### 4.1 权限分层模型

```
┌─────────────────────────────────────────┐
│           登录态校验（L1）               │
│   检查 Cookie/Token，未登录跳转登录页    │
├─────────────────────────────────────────┤
│           菜单级权限（L2）               │
│   后端返回有权限的菜单列表，前端渲染     │
├─────────────────────────────────────────┤
│           路由级权限（L3）               │
│   直接访问 URL 时校验是否有对应菜单权限  │
├─────────────────────────────────────────┤
│           按钮级权限（L4）               │
│   操作按钮渲染前校验权限码               │
└─────────────────────────────────────────┘
```

### 4.2 权限实现方案

**L1 — 登录态校验**（`SecurityLayout.tsx`）：

```typescript
const SecurityLayout: React.FC = ({ children }) => {
  const [isReady, setIsReady] = useState(false);

  useEffect(() => {
    const uin = Cookies.get('uin');
    if (!uin) {
      // 跳转登录，携带回调地址
      window.location.href = `/login?redirect=${encodeURIComponent(window.location.href)}`;
      return;
    }
    setIsReady(true);
  }, []);

  if (!isReady) return <PageLoading />;
  return <>{children}</>;
};
```

**L3 — 路由级权限**（`AuthWrapper.tsx`）：

```typescript
// 推荐通过 UmiJS wrappers 配置前置校验，而非组件挂载后校验
// config/routes/index.ts
{
  path: '/module-a/page-one',
  component: '@/pages/ModuleA/PageOne',
  wrappers: ['@/components/AuthWrapper'],
}

// src/components/AuthWrapper/index.tsx
const AuthWrapper: React.FC = ({ children }) => {
  const { menuList } = useSelector((s: RootState) => s.global);
  const location = useLocation();

  const hasPermission = useMemo(
    () => menuList.some((menu) => menu.url === location.pathname),
    [menuList, location.pathname],
  );

  if (!hasPermission) return <Redirect to="/403" />;
  return <>{children}</>;
};
```

**L4 — 按钮级权限**（`AuthButton.tsx`）：

```typescript
interface AuthButtonProps {
  permCode: string;           // 权限码
  children: React.ReactNode;
  fallback?: React.ReactNode; // 无权限时的降级展示
}

const AuthButton: React.FC<AuthButtonProps> = ({
  permCode,
  children,
  fallback = null,
}) => {
  const { permissions } = useSelector((s: RootState) => s.user);
  const hasAuth = permissions.includes(permCode);

  if (!hasAuth) return <>{fallback}</>;
  return <>{children}</>;
};

// 使用示例
<AuthButton permCode="module-a:create">
  <Button type="primary">新建</Button>
</AuthButton>
```

**组件开发约定：**

| 约定           | 说明                                               |
| -------------- | -------------------------------------------------- |
| 函数组件优先   | 禁止新增 Class 组件，存量逐步迁移                  |
| Props 类型声明 | 所有组件必须定义 Props 接口，禁止使用 `any`        |

### 6.2 状态管理规范

| 规范         | 说明                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 全局 vs 页面 | 跨页面共享的状态放 `src/models/`，页面私有状态放页面目录的 `model.ts`              |
| 异步处理     | 异步操作统一在 Effect 中处理，Reducer 只做纯同步更新                               |
| Loading 状态 | 使用 DVA 内置的 `loading` model，避免手动维护 loading 状态                         |
| 数据规范化   | 列表数据统一使用 `{ list: [], total: 0 }` 结构                                     |
| 命名规范     | Effect 用动词开头（`fetchList`、`createItem`），Reducer 用 `set` 前缀（`setList`） |

```typescript
// src/models/global.ts — 菜单数据缓存策略
*fetchMenus({ payload }, { call, put }) {
  const CACHE_KEY = 'menu_cache';
  const CACHE_VERSION_KEY = 'menu_cache_version';

  // 读取缓存
  const cachedVersion = sessionStorage.getItem(CACHE_VERSION_KEY);
  const cachedMenus = sessionStorage.getItem(CACHE_KEY);

  if (cachedVersion === payload.version && cachedMenus) {
    yield put({ type: 'setMenus', payload: JSON.parse(cachedMenus) });
    return;
  }

  // 请求新数据
  const { data } = yield call(fetchMenusApi, payload);
  sessionStorage.setItem(CACHE_KEY, JSON.stringify(data));
  sessionStorage.setItem(CACHE_VERSION_KEY, payload.version);
  yield put({ type: 'setMenus', payload: data });
}
```

## 十、部署配置规范

### 10.1 Nginx 配置模板

```nginx
server {
    listen 80;
    server_name admin.example.com;

    # 安全响应头
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header X-XSS-Protection "1; mode=block";
    add_header Referrer-Policy "strict-origin-when-cross-origin";

    # 静态资源强缓存（带 hash 的文件）
    location ~* \.(js|css|png|jpg|gif|ico|woff2?)$ {
        root /usr/share/nginx/html;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # HTML 文件不缓存（确保更新即时生效）
    location ~* \.html$ {
        root /usr/share/nginx/html;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # SPA 路由兜底
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass https://api.example.com/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
