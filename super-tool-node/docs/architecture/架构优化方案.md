# node-demo 后台服务架构优化方案

> 文档版本: v1.0 | 生成日期: 2026-04-01 | 分类: architecture

---

## 一、优化目标

基于对 node-demo（yoyo-node）现有项目的深度分析和 `后台服务架构设计.md` 中的目标架构设计，制定以下优化路线：

| 目标 | 优先级 | 预期效果 |
|------|--------|----------|
| 安全加固 | P0 | 消除密钥泄露和无鉴权漏洞 |
| TypeScript 迁移 | P1 | 提升代码质量和可维护性 |
| ORM 模型层引入 | P1 | 规范数据访问、支持迁移 |
| 统一中间件体系 | P1 | 认证、限流、错误处理标准化 |
| 测试体系建设 | P1 | 从 0% 提升到 ≥60% 覆盖率 |
| 框架升级 | P2 | Egg.js 2.x → 3.x |
| API 规范化 | P2 | RESTful + Swagger 文档自动生成 |

## 二、分阶段优化路线

### 第一阶段: 安全加固（1-2 周）

#### 2.1 敏感信息治理

**现状**: 数据库密码、Redis密码、S3密钥明文存储在代码仓库中。

**方案**:
```
1. 创建 .env 文件管理敏感信息（加入 .gitignore）
2. 创建 .env.example 作为模板（仅含变量名）
3. 移除 env_dev.yaml 中所有真实密码
4. 移除 config.default.js 中硬编码的密码
5. 使用 dotenv 或蓝鲸平台的环境变量注入机制
```

**config.default.js 改造示例**:
```javascript
// 改造前（危险）
xinyueDB: {
  host: 'gamedb.xyapp.vip.db',
  password: 'webapi@2012',  // 明文密码
}

// 改造后（安全）
xinyueDB: {
  host: process.env.GCS_MYSQL_XINYUE_HOST,
  password: process.env.GCS_MYSQL_XINYUE_PASSWORD,
}
```

#### 2.2 认证中间件引入

**现状**: 除 `/api/*` 签名验证外，业务路由无认证。

**方案**: 新增 JWT 认证中间件 + 路由白名单

```
app/middleware/
├── auth.ts              # JWT认证中间件（新增）
├── errorHandler.ts      # 全局错误处理中间件（新增）
├── rateLimit.ts         # 限流中间件（新增）
└── crypto.js            # 已有签名中间件（保留）
```

**认证中间件核心逻辑**:
```typescript
// 白名单路由跳过认证
const whiteList = ['/api/health', '/common/requestHelperApi'];

// 从 Cookie 中读取 bk_uid 并验证
// 或引入 JWT Token 双Token机制（参考架构设计文档）
```

#### 2.3 SQL 注入修复

**需修复文件列表**:
| 文件 | 问题 | 修复方式 |
|------|------|---------|
| `service/common.js` L43 | SQL 字符串直接拼接 WHERE | 改用参数化查询 |
| `service/main.js` L191 | `IN (${keys.join(',')})` | 改用 `?` 占位符 |
| `service/privilege.js` L308-312 | 动态 SQL 拼接 | 使用 ORM 查询构建器 |

### 第二阶段: TypeScript 迁移 + 代码重构（3-6 周）

#### 2.4 TypeScript 迁移策略

采用**渐进式迁移**，不一次性重写所有文件：

```
阶段一: 新增文件全部使用 TypeScript
阶段二: 从底层开始迁移 extend/ → middleware/ → service/ → controller/
阶段三: 迁移配置文件 config/
```

**tsconfig.json 配置**（参照架构设计文档）:
```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "strict": true,
    "noImplicitAny": true,
    "esModuleInterop": true,
    "experimentalDecorators": true,
    "outDir": "./dist",
    "paths": {
      "@/*": ["app/*"]
    }
  }
}
```

#### 2.5 代码重复消除

**重点重构: helper.js 的 HTTP 代理方法**

将 5 个高度重复的方法抽象为统一的签名请求器：

```typescript
// app/extend/helper.ts（重构后）
class RequestBuilder {
  private buildSignature(url: string, params: object, secret: string): string { ... }
  private async getCustomHeaders(rtx: string, table: string): Promise<Headers> { ... }

  async request(url: string, params: object, options?: RequestOptions): Promise<any> {
    const signature = this.buildSignature(url, params, this.config.crypto.secret);
    const headers = await this.getCustomHeaders(rtx, options?.headerTable);
    // 统一的请求逻辑
  }
}
```

**重点重构: Service 基类抽取**

```typescript
// app/service/base.ts
export default class BaseService extends Service {
  protected get db() { return this.app.mysql.get('defaultDB'); }
  protected get dnfDb() { return this.app.mysql.get('dnfCmsDB'); }

  // 分页查询封装
  protected async paginate<T>(table: string, options: PaginateOptions): Promise<PaginateResult<T>> { ... }

  // 通用CRUD
  protected async findById(table: string, id: number): Promise<any> { ... }
  protected async insertOrUpdate(table: string, data: any): Promise<any> { ... }
  protected async softDelete(table: string, id: number, rtx: string): Promise<any> { ... }
}
```

#### 2.6 错误处理体系

**全局错误中间件**（参照架构设计文档）:

```typescript
// app/middleware/errorHandler.ts
export default () => {
  return async (ctx: Context, next: () => Promise<void>) => {
    try {
      await next();
    } catch (err: any) {
      ctx.logger.error('[ErrorHandler]', err);
      const status = err.status || err.code || 500;
      ctx.body = {
        code: status,
        message: err.msg || err.message || 'Internal Server Error',
        data: null,
        timestamp: Date.now(),
      };
      ctx.status = status >= 100 && status < 600 ? status : 500;
    }
  };
};
```

**统一错误码管理**:

```typescript
// app/constants/errorCodes.ts
export const ErrorCodes = {
  PARAM_EMPTY: { code: 10001, msg: '参数不能为空' },
```

### 第三阶段: ORM 引入 + 数据库规范（4-8 周）

#### 2.7 Sequelize ORM 引入

**迁移策略**: 将 `egg-mysql` 逐步替换为 `egg-sequelize`

```
1. 安装 egg-sequelize + sequelize + mysql2
2. 将 app/models/*.sql 转化为 Sequelize 模型定义
3. 逐个 Service 迁移 DB 调用
4. 移除 egg-mysql 依赖
```

**模型定义示例**（对应现有 privilege.sql）:

```typescript
// app/model/privilege.ts
export default (app: Application) => {
  const Privilege = app.model.define('privilege', {
    id: { type: INTEGER.UNSIGNED, autoIncrement: true, primaryKey: true },
    pId: { type: STRING(17), field: 'p_id', comment: '后台生成的特权id' },
    gId: { type: STRING(17), field: 'g_id', comment: '套餐id' },
    gameId: { type: INTEGER, field: 'game_id', allowNull: false },
    type: { type: ENUM('1','2','3','4','5','6','7'), allowNull: false },
    title: { type: STRING(50), allowNull: false },
    status: { type: ENUM('2','3'), defaultValue: '3' },
    isDeleted: { type: ENUM('0','1'), field: 'is_deleted', defaultValue: '0' },
    // ...其他字段
  }, {
    tableName: 'privilege',
    timestamps: false,
    paranoid: false,
  });

  Privilege.associate = () => {
    Privilege.hasMany(app.model.PrivilegeProps, { foreignKey: 'p_id', as: 'props' });
  };

  return Privilege;
};
```

## 六、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| TypeScript 迁移导致线上故障 | 中 | 高 | 渐进式迁移、完善测试、灰度发布 |
| ORM 迁移数据不兼容 | 低 | 高 | 先只读迁移、对比测试 |
| 框架升级 API 不兼容 | 中 | 中 | 参考 Egg.js 迁移指南、逐步验证 |
| 人力不足 | 高 | 中 | 按优先级分阶段执行 |
