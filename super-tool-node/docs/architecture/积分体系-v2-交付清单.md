## 4. HTTP API 清单

### 4.1 C 端（用户自用，需 `auth`，部分挂 `rateLimit + idempotency`）

> **写入类**接口客户端**必须**在请求头携带 `Idempotency-Key: <UUID v4>`，24 小时内同 Key 重复请求会返回首次响应（响应头多一个 `x-idempotent-replayed: true`）。
>
> **限流策略**：claim/sign 10/min、exchange 5/min。

| Method | Path                                                              | 限流   | 幂等 | 说明                                          |
| ------ | ----------------------------------------------------------------- | ------ | ---- | --------------------------------------------- |
| GET    | `/api/tasks?category=newbie\|daily\|achievement\|monthly\|yearly` | —      | —    | 任务列表（含进度）                            |
| POST   | `/api/tasks/:code/claim`                                          | 10/min | ✅   | 领取任务奖励                                  |
| POST   | `/api/sign`                                                       | 10/min | ✅   | 每日签到                                      |
| GET    | `/api/sign/status?yearMonth=YYYY-MM`                              | —      | —    | 签到日历 / 当月状态                           |
| GET    | `/api/points-mall/items?category=`                                | —      | —    | 商城商品列表                                  |
| POST   | `/api/points-mall/exchange`                                       | 5/min  | ✅   | 兑换商品（body: `{ itemId, deliveryInfo? }`） |
| GET    | `/api/points-mall/orders?page&pageSize`                           | —      | —    | 我的兑换记录                                  |

**统一响应体**（`BaseController.success`）：

```json
{ "code": 200, "message": "success", "data": <T>, "timestamp": 1761000000000 }
```

## 5. 中间件（新增 1 个）

### `app/middleware/idempotency.ts`

| 项                   | 值                                                  |
| -------------------- | --------------------------------------------------- |
| 工厂签名             | `(options: { ttlHours?: number }, app)`             |
| Redis Key            | `idem:{userId}:{Idempotency-Key}`                   |
| TTL                  | 24 小时（可由 `points.idempotency_ttl_hours` 配置） |
| 命中行为             | 返回首次响应 + 响应头 `x-idempotent-replayed: true` |
| 仅缓存 2xx           | ✅ 4xx/5xx 不缓存（允许客户端重试）                 |
| Redis 不可用         | 降级放行（不阻塞业务）                              |
| Idempotency-Key 格式 | UUID v4，否则返回 400                               |

**单元测试**：6 个 case 全绿，覆盖未传 key / 未登录 / UUID 校验 / 命中重放 / 4xx 不缓存 / 多用户隔离。

## 10. 联调要点（前端对接）

### 10.1 客户端必须实现

1. **生成 UUID v4** 作为 `Idempotency-Key` 请求头（推荐 `crypto.randomUUID()`），重试用同一个 key
2. 处理 `429` 限流响应（`X-RateLimit-Remaining` 头可参考剩余次数）
3. 处理 `x-idempotent-replayed: true` 响应头（提示用户操作已成功，无需重复）

### 10.2 错误码约定

| HTTP 状态 | 业务场景                              |
| --------- | ------------------------------------- |
| 400       | 参数错误 / Idempotency-Key 非 UUID v4 |
| 403       | 权限不足（管理端）                    |
| 404       | 任务/商品/订单不存在                  |
| 422       | 参数验证失败（带 `errors` 数组）      |
| 429       | 触发限流                              |

### 10.3 时区

- 所有时间字段采用 `DATETIME`（服务器时区，默认 UTC+8）
- 签到日期 `sign_date` 采用 `DATE`（按服务器日历日，0 点切换）
- 客户端跨时区显示请用 ISO8601 + 自行转换
