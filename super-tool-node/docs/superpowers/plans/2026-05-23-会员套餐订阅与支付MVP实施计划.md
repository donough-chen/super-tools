# 会员套餐订阅与支付 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `member-subscription-mvp` 分支实装会员套餐订阅 + 支付（Mock Provider）+ 订单管理 + 到期定时 + H5 4 页 + 管理端订单只读，形成"下单 → 支付 → 开通 → 通知 → 到期"完整业务闭环。

**Architecture:** 后端用 PaymentProvider 适配器架构（Mock 实装 + Wechat 占位）；订单/支付双表分离；事务嵌套拆分（外层只更状态，activatePaidPlan 自带独立事务）；调度器幂等键防重发。前端 H5 重写 4 页（plans/cashier/orders/orders[id]）+ 管理端只读订单列表。

**Tech Stack:** Egg.js 3 + Sequelize 6 + MySQL 8 / TypeScript 5.4 / React 18 / UmiJS 3.5 / Antd 5 / Jest 26 / @testing-library/react 14 / jotai

**Spec Reference:** `docs/superpowers/specs/2026-05-23-会员套餐订阅与支付MVP设计文档.md`

**分支:** `member-subscription-mvp`（基于 master @ `e6ce79d`，已存在）

```typescript
import { MockProvider } from '../mock';

describe('MockProvider', () => {
  const mock = new MockProvider();

  it('createPrepay returns mockToken + cashierUrl', async () => {
    const result = await mock.createPrepay({
      paymentNo: 'MP_TEST_1',
      amount: 6.8,
      subject: '月度会员订阅',
      userId: 1,
      notifyUrl: 'http://localhost:7001/api/payments/mock/notify',
    });
    expect(result.prepayData.mockToken).toMatch(/^mock_MP_TEST_1_/);
    expect(result.prepayData.amount).toBe(6.8);
    expect(result.cashierUrl).toBe('/member/cashier?paymentNo=MP_TEST_1');
  });

  it('verifyCallback success on valid payload', async () => {
    const body = JSON.stringify({ paymentNo: 'MP_T1', amount: 6.8, providerTradeNo: 'WX_123' });
    const result = await mock.verifyCallback({}, body);
    expect(result.success).toBe(true);
    expect(result.paymentNo).toBe('MP_T1');
    expect(result.amount).toBe(6.8);
    expect(result.providerTradeNo).toBe('WX_123');
  });

  it('verifyCallback fails on invalid JSON', async () => {
    const result = await mock.verifyCallback({}, 'not_json');
    expect(result.success).toBe(false);
    expect(result.error).toBe('invalid JSON');
  });

  it('verifyCallback fails on missing paymentNo', async () => {
    const result = await mock.verifyCallback({}, JSON.stringify({ amount: 1 }));
    expect(result.success).toBe(false);
    expect(result.error).toBe('missing paymentNo');
  });

  it('verifyCallback fails on missing amount', async () => {
    const result = await mock.verifyCallback({}, JSON.stringify({ paymentNo: 'X' }));
    expect(result.success).toBe(false);
    expect(result.error).toBe('missing/invalid amount');
  });

  it('verifyCallback auto-generates providerTradeNo when omitted', async () => {
    const result = await mock.verifyCallback({}, JSON.stringify({ paymentNo: 'X', amount: 1 }));
    expect(result.success).toBe(true);
    expect(result.providerTradeNo).toMatch(/^MOCK_\d+$/);
  });

  it('queryStatus always returns pending', async () => {
    const status = await mock.queryStatus('any');
    expect(status).toBe('pending');
  });
});
```

```tsx
              ⚠️ 当前为开发期 Mock 支付，生产环境将切换为真实微信支付
            </div>
          </>

      </main>

      <AppModal

        content={confirmModal.type === 'success' ? '将触发订单开通会员 + 三条通知（支付成功/套餐开通/积分变动）' : '订单将保持待支付状态，可重新尝试支付'}
```

```tsx
  const sentinelRef = useRef<HTMLDivElement>(null);
```

### 关键风险

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 023 通知模板与 018 已有种子冲突 | INSERT IGNORE 重复执行 | 已用 `NOT EXISTS` 子查询防重 |

| Windows 下 npm run dev 多端口冲突 | T17 三个 dev 同跑 | 端口配置：后端 7001 / admin 8000 / H5 自动；如冲突按提示改 |
| schedule cron 在 Windows 时区不正确 | egg-schedule 默认 UTC | 启动日志确认 cron 解析后的下次执行时间；如错可在 schedule 配置加 `cronOptions: { tz: 'Asia/Shanghai' }` |
| 测试 ts-jest 26 + TS 5.4 hoist-jest bug | 后端 service 单测用 .ts | 后端 .ts 测试可正常跑（ts-jest 配置已在；C2b 经验仅前端有此问题） |

### 回滚策略

- **半路撤回**：在分支内 `git reset --hard <last-good-commit>` 重做有问题的 Task
- **整体撤回**：分支已 merge → `git revert -m 1 <merge-commit>`，DB 三个迁移可手动 DROP 表 + 删权限
- **DB 回滚**：保留撤回 SQL 草稿（在 follow-up 中维护）：
  ```sql
  DROP TABLE IF EXISTS member_payments;
  DROP TABLE IF EXISTS member_orders;
  DELETE FROM permissions WHERE code LIKE 'member:order:%';
  DELETE FROM notification_types WHERE code IN ('BUSINESS_PAYMENT_SUCCESS','BUSINESS_PAYMENT_FAIL');
  -- system_configs 中 group='payment' 行根据需要保留或删除
  ```
