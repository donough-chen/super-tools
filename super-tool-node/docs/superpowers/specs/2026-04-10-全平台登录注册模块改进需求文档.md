## 一、评估报告改进方案复审与优化建议

### 1.1 评估报告改进方案合理性评审

| 方案 | 评审结论 | 合理性 | 说明 |
|------|---------|--------|------|
| **方案一：`user_profiles` 扩展表** | ✅ 合理，有优化空间 | ⭐⭐⭐⭐ | 1:1 扩展表策略正确，避免了对 `users` 主表的侵入；但部分字段归类需调整 |
| **方案二：会员等级体系** | ⚠️ 部分合理，需降级 | ⭐⭐⭐ | 表结构设计合理，但会员体系属于 **P2 业务扩展**，不应与 P0 登录注册改进混为一谈 |
| **方案三：登录注册接口扩展** | ✅ 核心合理，需深化 | ⭐⭐⭐⭐ | 接口方向正确，但缺少完整的 Service 层设计、错误处理链路和安全防护细节 |

### 1.2 识别到的不足与优化建议

#### 🔴 不足一：会员体系与登录注册改进耦合过深

**问题**：评估报告将 `member_levels`、`user_members`、`points_logs` 三张会员表（方案二）与登录注册改进放在同一优先级，导致需求范围膨胀。

**优化**：
- 会员等级体系拆分为独立需求文档，降级为 **P2**
- 本文档聚焦 **P0（多端登录）** + **P1（用户扩展信息）**，保持单一职责
- `user_profiles` 表中去掉 `points`/`level` 字段（这些属于会员体系）

#### 🔴 不足二：微信登录缺少多场景区分

**问题**：报告中 `wechatLogin()` 接口设计将小程序、公众号、开放平台三种微信登录混合在同一入口，但这三种场景的微信 API 调用方式完全不同：

| 场景 | 微信 API | 返回值 | 场景特点 |
|------|---------|--------|---------|
| 小程序 | `sns/jscode2session` | `openid + session_key` | 静默登录，无需用户确认 |
| 公众号H5 | `sns/oauth2/access_token` | `openid + access_token` | OAuth2 网页授权 |
| 开放平台 | `sns/oauth2/access_token` | `openid + unionid` | App 内拉起微信 |

**优化**：统一入口保留，但 Service 层必须按 `platform` 参数做策略分发，内部分别调用对应微信 API，避免单一方法膨胀为超大函数。

#### 🟡 不足三：`user_profiles` 表字段设计不够精简

**问题**：报告中的 `user_profiles` 表混入了 `push_token` 和 `push_platform` 设备推送字段，这些应属于 `user_devices` 表（一个用户可能有多个设备）。

**优化**：
- `push_token`、`push_platform` 从 `user_profiles` 移除
- 新增 `user_devices` 表，支持一对多关系（用户 → 多设备）
- `user_profiles` 纯粹存储个人资料和偏好设置

#### 🟡 不足四：手机号注册/登录缺少验证码校验的完整链路

**问题**：报告中手机号登录的 `phoneLogin()` 方法只列出了参数校验，未描述：
- 验证码校验的原子性（防并发消费同一验证码）
- 验证码错误次数限制（防暴力破解）
- 手机号登录时自动注册的策略（"注册即登录"）

**优化**：本文档补充完整的验证码校验链路和防护机制。

#### 🟡 不足五：`user_type` 与 RBAC 重叠问题被低估

**问题**：报告将此问题标为 P2，但当前 `auth` 中间件（`checkPermission.ts`）中有 `if (user.userType === 3)` 硬编码判断超级管理员，如果不解决，新增的多端登录用户将面临权限判断不一致的风险。

**优化**：
- 短期方案：保留 `user_type` 作为快速鉴权字段（只在中间件中使用），但 **废弃 `user_type` 的 2（管理员）语义**，统一由 RBAC `roles` 控制
- `user_type` 简化为：`1=普通用户`、`3=超级管理员`（仅作中间件快捷跳过权限检查用）
- 新增用户一律 `user_type=1`，管理权限完全由角色赋予
- 在 JWT payload 中增加 `roles` 字段，减少运行时查库

#### 🟢 不足六：缺少账号绑定/解绑功能

**问题**：评估报告只覆盖了"注册+登录"场景，但遗漏了用户注册后绑定/解绑其他登录方式的需求（如：手机号注册用户后续绑定微信）。

**优化**：本文档新增「账号绑定管理」模块。

## 二、需求概览

### 2.1 需求目标

基于现有 `super-tool-node` 的 SSO 认证架构，扩展全平台登录注册能力，实现：

1. **微信小程序一键登录**（P0）：支持 `wx.login()` 静默授权 + 可选手机号获取
2. **手机号验证码登录/注册**（P0）：一号通行，新用户自动注册
3. **微信公众号H5登录**（P0）：OAuth2 网页授权
4. **用户扩展信息管理**（P1）：`user_profiles` + `user_devices`
5. **多端账号绑定管理**（P1）：绑定/解绑手机号、微信、邮箱
6. **登录安全增强**（P1）：异地登录检测、设备管理、登录失败锁定

### 2.2 需求范围（IN/OUT）

| IN（本期实现） | OUT（后续迭代） |
|---------------|----------------|
| 微信小程序登录 | Apple ID 登录 |
| 微信公众号H5登录 | Google/GitHub OAuth |
| 手机号验证码登录/注册 | 会员等级体系（`member_levels` 等 3 张表） |
| 用户扩展信息（`user_profiles`） | 积分流水 |
| 设备管理（`user_devices`） | 支付宝登录 |
| 账号绑定/解绑 | 人脸识别登录 |
| 登录安全增强 | 多租户支持 |

### 2.3 涉及平台

| 平台 | 登录方式 | 注册方式 | 优先级 |
|------|---------|---------|--------|
| 微信小程序 | 微信授权一键登录 | 静默注册（首次登录即注册） | P0 |
| 移动H5 | 手机号+验证码 / 微信公众号授权 | 手机号+验证码 | P0 |
| 官网PC | 用户名密码 / 邮箱密码 | 邮箱+密码（已有） | 已实现 |
| iOS/Android | 手机号+验证码 / 微信 | 手机号+验证码 | P0 |
| 管理后台 | 用户名+密码 | 管理员创建（已有） | 已实现 |

### 3.3 M2：手机号验证码登录/注册模块

#### 3.3.1 核心设计：「登录即注册」策略

手机号验证码场景采用"一号通行"策略：验证通过后，系统自动判断是新用户还是老用户。

```
输入: phone + code + clientId

              ┌─────────────┐
              │  校验验证码   │
              └──────┬──────┘
                     │ 通过
              ┌──────▼──────┐
              │  查 users 表 │
              │ WHERE phone  │
              └──────┬──────┘
                ┌────┴────┐
           存在 │         │ 不存在
          ┌─────▼────┐  ┌──▼──────────┐
          │ 直接登录  │  │ 自动注册     │
          │ 生成Token │  │ + 分配角色   │
          │          │  │ + 生成Token  │
          └──────────┘  └─────────────┘
```

#### 3.3.2 验证码发送增强

当前 `sendVerifyCode()` 仅模拟，需对接实际短信服务并增加防护：

**频率限制**（基于 Redis）：

| 维度 | 限制 | Redis Key 格式 | TTL |
|------|------|----------------|-----|
| 单号码 | 60秒内不可重发 | `sms:interval:{phone}` | 60s |
| 单号码 | 每日上限10条 | `sms:daily:{phone}:{date}` | 86400s |
| 单IP | 每小时上限20条 | `sms:ip:{ip}:{hour}` | 3600s |
| 全局 | 每分钟100条 | `sms:global:{minute}` | 60s |

**验证码校验增强**：

```typescript
// 验证码校验伪代码
async verifyCode(phone: string, code: string, type: string): Promise<boolean> {
  // 1. 获取分布式锁（防并发消费同一验证码）
  const lock = await this.service.cache.acquireLock(`verify:${phone}:${type}`, 5);
  if (!lock) throw new Error('操作过于频繁');

  try {
    // 2. 检查错误次数（防暴力破解，5次锁定30分钟）
    const failKey = `verify:fail:${phone}:${type}`;
    const failCount = await this.app.redis.get(failKey);
    if (Number(failCount) >= 5) {
      throw new Error('验证码错误次数过多，请30分钟后再试');
    }

    // 3. 查询最新未使用的验证码
    const record = await this.ctx.model.VerifyCode.findOne({
      where: { target: phone, type, isUsed: 0 },
      order: [['created_at', 'DESC']],
    });

    if (!record || record.code !== code) {
      // 记录失败次数
      await this.app.redis.incr(failKey);
      await this.app.redis.expire(failKey, 1800);
      return false;
    }

    if (new Date(record.expireAt) < new Date()) {
      return false; // 已过期
    }

    // 4. 标记已使用
    await record.update({ isUsed: 1, usedAt: new Date() });
    // 5. 清除失败计数
    await this.app.redis.del(failKey);
    return true;
  } finally {
    await this.service.cache.releaseLock(`verify:${phone}:${type}`, lock);
  }
}
```

### 3.5 M4：账号绑定管理模块

用户注册后，可以绑定/解绑其他登录方式：

**支持的绑定操作**：

| 操作 | 接口 | 前置条件 |
|------|------|---------|
| 绑定手机号 | `POST /api/users/bindPhone` | 需验证码确认 |
| 绑定微信 | `POST /api/users/bindWechat` | 需微信授权 code |
| 绑定邮箱 | `POST /api/users/bindEmail` | 需邮箱验证码确认 |
| 解绑手机号 | `POST /api/users/unbindPhone` | 至少保留一种登录方式 |
| 解绑微信 | `POST /api/users/unbindWechat` | 至少保留一种登录方式 |
| 解绑邮箱 | `POST /api/users/unbindEmail` | 至少保留一种登录方式 |

**安全约束**：
- 解绑任何登录方式前，必须确保用户至少保留一种可用的登录方式
- 校验公式：`count(有效登录方式) - 1 >= 1`
- 有效登录方式 = `phone` + `email`（有 `password_hash`）+ `user_oauth` 记录数

### 3.6 M5：安全增强模块

#### 3.6.1 异地登录检测

```typescript
// 登录时比对历史 IP 归属地
const lastLocation = user.lastLoginIp ? await ipToLocation(user.lastLoginIp) : null;
const currentLocation = await ipToLocation(ctx.ip);

if (lastLocation && lastLocation.city !== currentLocation.city) {
  // 1. 标记为异地登录
  // 2. 发送安全通知（站内信 + 短信/邮件）
  // 3. 响应中返回 abnormalLogin: true
  await this.ctx.model.Notification.create({
    userId: user.id,
    type: 'security',
    title: '异地登录提醒',
    content: `您的账号在 ${currentLocation.city} 登录，如非本人操作请立即修改密码`,
  });
}
```

#### 3.6.2 登录失败自动锁定

基于 Redis 的分级锁定机制（增强现有 `recordLoginFailure`）：

| 失败次数 | 处理策略 | 锁定时间 |
|---------|---------|---------|
| 1-4 次 | 正常提示"用户名或密码错误" | 不锁定 |
| 5 次 | 要求输入图形验证码 | 不锁定 |
| 8 次 | 临时锁定账号 | 15 分钟 |
| 10 次 | 锁定账号 + 通知安全团队 | 60 分钟 |
| 15 次 | 永久锁定，需人工解封 | 永久 |

## 九、验收标准

### 9.1 功能验收

#### P0 - 微信小程序登录

| # | 验收项 | 验证方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 小程序首次登录自动注册 | 使用未注册微信号调用 `/wechat-login` | 返回 `isNewUser: true` + 有效 Token |
| 2 | 小程序再次登录直接通过 | 使用已注册微信号调用 `/wechat-login` | 返回 `isNewUser: false` + 有效 Token |
| 3 | 小程序获取手机号 | 传入 `encryptedData` + `iv` | 用户记录自动关联手机号 |
| 4 | user_oauth 记录正确 | 查数据库 | `platform=wechat_mp`, `open_id` 和 `union_id` 正确 |
| 5 | Token 有效期正确 | 检查 `expiresIn` | 等于 `oauth_clients` 中 miniprogram_client 的 TTL |
| 6 | 会话写入正确 | 查 `user_sessions` 表 | `platform=miniprogram`, `is_active=1` |
| 7 | 登录日志写入 | 查 `login_logs` 表 | `login_type=wechat`, `platform=miniprogram` |
| 8 | code 无效时错误处理 | 传入过期/无效 code | 返回 400 + 明确错误信息 |
| 9 | 被禁用用户拒绝登录 | 禁用用户后登录 | 返回 403 |

#### P0 - 手机号验证码登录

| # | 验收项 | 验证方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 发送验证码成功 | 调用 `/send-code` | 返回成功 + `verify_codes` 表有记录 |
| 2 | 60秒内重发拒绝 | 60秒内再次请求 | 返回 429 + "请60秒后重试" |
