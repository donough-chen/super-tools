## 0. 设计目标与边界

**目标**：在 H5 端交付一套完整的积分成长体系用户界面，与已上线的后端积分/会员/任务/商城接口对接，达到端到端业务闭环（签到 → 任务领取 → 商品兑换 → 等级升降）。

**范围（本 Spec 覆盖）**：
- 5 大核心页面 + 9 个子页面 / 跳转页
- 4 个新 Store + 4 个新 Service + 1 套类型定义
- 数据层 Mock + 后端真接口对接
- 跨页面数据同步策略

**非范围**：
- 后端接口开发（已由 plan-v2 / A / B 计划完成）
- 全屏升级动效（首期降级为 Toast）
- 商城 Banner / 限时特惠 / 分类的后端接口（前端硬编码 + Mock 兜底）

## 4. Service 层设计

### 4.1 后端响应格式（已确认）

```typescript
// 成功
{ code: 200, message: "success", data: <T>, timestamp: 1761000000000 }
// 错误
{ code: 400|401|403|404|422|429|500, message: string, errors?, timestamp }
```

写入接口必传 `Idempotency-Key: <UUID v4>` 请求头，否则返回 400。重放命中返回响应头 `x-idempotent-replayed: true`。

### 4.2 Service 文件清单

| 文件 | 类型 | 职责 |
|---|---|---|
| `service/member.ts` | 扩展 | 追加 `getMemberLevels` / `getMemberBenefits` / `getPointsLogs` / `dailySign` |
| `service/sign.ts` | 新增 | 签到状态查询 + 签到提交 |
| `service/task.ts` | 新增 | 任务列表查询 + 任务领取 |
| `service/pointsMall.ts` | 新增 | 商品列表 + 兑换 + 兑换订单 |
| `utils/idempotency.ts` | 新增 | UUID v4 幂等 Key 生成器 |

### 4.3 接口与后端路由对照

| 前端方法 | HTTP | 后端路径 | 备注 |
|---|---|---|---|
| `getMemberLevels` | GET | `/api/member/levels` | 公开，无 auth |
| `getMemberBenefits` | GET | `/api/member/benefits` | 需 auth |
| `getPointsLogs(params)` | GET | `/api/member/points-logs` | 分页 + 类型/时间筛选 |
| `dailySign(idemKey)` | POST | `/api/member/daily-sign` | 写入，需 Idempotency-Key |
| `getSignStatus` | GET | `/api/sign/status` | 需 auth |
| `doSign(idemKey)` | POST | `/api/sign` | 写入，限流 10/min |
| `getTasks` | GET | `/api/tasks` | 任务列表 |
| `claimTask(code, idemKey)` | POST | `/api/tasks/:code/claim` | 写入，限流 10/min |
| `getMallItems(params)` | GET | `/api/points-mall/items` | 商品列表 |
| `exchangeItem(itemId, idemKey)` | POST | `/api/points-mall/exchange` | 写入，限流 5/min |
| `getMallOrders(params)` | GET | `/api/points-mall/orders` | 兑换订单 |

> 后端有 `/api/member/daily-sign` 和 `/api/sign` 两个签到接口。前端**统一使用 `/api/sign`**（带连签状态返回），`/api/member/daily-sign` 暂不调用，由 service 层封装为冗余备份。

### 4.4 Service 层适配策略

针对后端字段缺失，service 层提供容错适配：

```typescript
// 商品图片字段适配
const adaptItem = (raw: any): MallItem => ({
  ...raw,
  images: (raw.images && raw.images.length) ? raw.images : [raw.image || DEFAULT_ITEM_IMG],
  pointsActual: raw.pointsActual ?? raw.pointsRequired,
  category: raw.category || 'benefit',
  tags: raw.tags || [],
});
```

## 6. Store 层设计

### 6.1 `useSignStore`

```
state:
  status: SignStatus | null
  loading: boolean
  submitting: boolean
  fetchedAt: number

actions:
  fetchStatus(force?: boolean)        // 5min TTL
  submitSign(): Promise<SignResult>   // 内部生成 idemKey；成功后强刷 useMemberStore
  reset()
```

### 6.2 `useTaskStore`

```
state:
  tasks: TaskItem[]
  groupedTasks: Record<TaskType, TaskItem[]>  // 衍生缓存
  loading: boolean
  fetchedAt: number

actions:
  fetchTasks(force?)
  claimTask(code: string): Promise<TaskClaimResult>
    └─ 成功后局部更新 task.status='claimed' + 强刷 useMemberStore
  reset()
```

### 6.3 `usePointsLogStore`

```
state:
  logs: PointsLog[]
  total: number
  page: number
  pageSize: 20
  filter: { type?: PointsLogType | 'all'; range?: 'thisMonth'|'lastMonth'|'last3Months'|'all' }
  loading: boolean
  hasMore: boolean
  fetchedAt: number

actions:
  fetchLogs(reset?: boolean)         // reset=true 清空重拉，否则追加分页
  setFilter(filter)                  // 切换筛选 → 自动 reset 重拉
  loadMore()
  reset()

派生（组件内 useMemo）:
  - 即将过期：logs.filter(l => l.expireAt && diff <= 30 days)
  - 月度构成：reduce by type
```

### 6.4 `usePointsMallStore`

```
state:
  items: MallItem[]
  itemsLoading: boolean
  itemsFetchedAt: number
  itemDetailCache: Record<number, MallItem>
  orders: MallOrder[]
  ordersLoading: boolean
  ordersFetchedAt: number

actions:
  fetchItems(force?)
  fetchItemDetail(id): Promise<MallItem | null>   // 优先 items.find，否则 fetch 单条
  exchange(itemId): Promise<{ orderId: number }>
    └─ 成功后强刷 useMemberStore + 清空 ordersFetchedAt 触发下次重拉
  fetchOrders(force?, status?)
  reset()
```

## 7. 关键交互流程

### 7.1 签到流程

```
触发：会员中心今日任务区域 / 任务中心日常 Tab / 签到按钮

1. 前置检查：useSignStore.status.signedToday ? 提示"今日已签到" : 继续
2. 调用 useSignStore.submitSign()
   ├─ 生成 idemKey (utils/idempotency.ts)
   ├─ POST /api/sign 携带 Idempotency-Key
   └─ 错误处理：429 限流提示 / 401 跳登录 / 其他 toast.message
3. 成功：
   ├─ Toast 浮层 "🎉 获得 +N 积分（连签 X 天）"
   ├─ 更新 useSignStore.status
   ├─ useMemberStore.fetchMemberInfo(true)
   └─ （可选）会员中心顶部积分数字滚动动效
```

### 7.2 商品兑换流程

```
触发：商品详情页「立即兑换 X 积分」按钮

1. 前置校验（前端，避免无谓请求）：
   - memberInfo.points < item.pointsActual → 弹窗"积分不足，去做任务"
   - item.exclusiveLevel 不满足 → 弹窗"等级不足"
   - item.monthlyUsed >= item.monthlyLimit → 弹窗"本月已达上限"

2. 弹出二次确认 AppModal：
   商品名 | 原价（划线） | 等级折扣 | 实付 | 兑换后余额 | "虚拟商品不可退款"警告

3. 用户确认 → usePointsMallStore.exchange(itemId)
   ├─ 生成 idemKey
   ├─ POST /api/points-mall/exchange
   └─ 错误处理：透传 backend message

4. 成功：
   ├─ safeNavigate(`/points-mall/exchange-success?orderId=X&itemId=Y`)
   ├─ useMemberStore.fetchMemberInfo(true)
   └─ usePointsMallStore.ordersFetchedAt = 0  (失效缓存)
```

### 7.3 任务领取流程

```
任务卡片按钮（按 status 不同形态）：
  - status=in_progress + 有 jumpPath → 「去完成」→ safeNavigate(jumpPath)
  - status=completed                 → 「领取」→ claimTask
  - status=claimed                   → 灰色「已领取」
  - status=locked                    → 灰色不可点

claimTask(code) 流程：
  POST /api/tasks/:code/claim (idemKey)
  ├─ 成功：toast "+X 积分" + 局部更新 task.status='claimed' + 强刷 useMemberStore
  └─ 失败：toast 错误信息
```

### 7.4 等级升级展示（被动触发）

```
useMemberStore.fetchMemberInfo 内部：
  - 对比 prev.level.level vs newData.level.level
  - 如果 newLevel > prevLevel：
    - 在 store 中标记 lastLevelUpAt = Date.now() + lastLevelUp = newLevel
    - 会员中心页 useEffect 监听 lastLevelUpAt 变化 → 展示 Toast「🎉 恭喜升级到{newLevel.name}」
    - 首期不做全屏动效
```

## 10. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 401 未登录 | request 拦截器统一处理（已存在），跳 `/login` |
| 429 限流 | toast「操作太频繁，请稍后再试」 |
| 400 业务错误（积分不足/已签到/等级不足） | 透传 `message` 到 toast 或弹窗 |
| 网络超时 | 骨架屏 + 重试按钮（10s 超时） |
| 空数据 | 各页面按设计稿空状态规范展示（图标+标题+描述+按钮） |
| Idempotency-Key 重放 | 后端响应头 `x-idempotent-replayed: true`，前端无需特殊处理 |
