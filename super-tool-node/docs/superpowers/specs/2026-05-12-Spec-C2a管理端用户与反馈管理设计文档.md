## 1. 概述与范围

### 1.1 目标

为管理端补齐 `/users`（用户管理）和 `/feedback`（反馈管理）两个二级模块的完整后台能力，与 Spec-C1（系统管理 4 页）共同形成"系统级管控"闭环。

### 1.2 不在范围（明确排除）

| 排除项 | 归属 |
|---|---|
| 会员等级 / 套餐 / 积分 / 签到管理 | Spec-C2b |
| C 端 `/feedback` 提交页 | 已实装，不变 |
| C 端用户 profile / device / address 自管理 | 已实装，不变 |
| 用户 ↔ 角色直接绑定（user:assign-roles） | 留 backlog（init.sql 权限码已占位，路由未挂） |
| 用户级直接授权（user:permission:grant/revoke） | 留 backlog（同上） |

### 2.2 接口 1：重置密码 `POST /api/admin/users/:id/reset-password`

#### 请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `newPassword` | string | 是 | 长度 8-50 |

#### 响应

```json
{ "code": 200, "message": "密码已重置", "data": null }
```

#### Service 签名

```typescript
// app/service/user.ts 新增
async adminResetPassword(adminId: number, targetUserId: number, newPassword: string): Promise<void>
```

#### 实现要点

```typescript
async adminResetPassword(adminId: number, targetUserId: number, newPassword: string) {
  const user = await this.ctx.model.User.findByPk(targetUserId);
  if (!user) this.ctx.throw(404, '用户不存在');

  // 防止把自己锁死（admin 重置自己密码应走自助 changePassword）
  if (adminId === targetUserId) {
    this.ctx.throw(400, '请通过"修改密码"修改自己的密码');
  }

  await (user as any).update({ passwordHash: await bcrypt.hash(newPassword, 12) });
  await this.clearCache(`${this.CACHE_PREFIX}${targetUserId}`);
}
```

#### Controller 实现

```typescript
async resetPassword() {
  this.validate({ newPassword: { type: 'string', min: 8, max: 50 } });
  const id = Number(this.ctx.params.id);
  const adminId = (this.ctx.state as any).user.id;
  const { newPassword } = this.ctx.request.body;

  let beforeData: any = null;
  try {
    const u = await this.service.user.findById(id);
    beforeData = this._stripSensitive(u);
  } catch { /* ignore */ }

  try {
    await this.service.user.adminResetPassword(adminId, id, newPassword);
    await this.service.audit.log({
      module: 'user', action: 'reset-password',
      bizType: 'user', bizId: id,
      beforeData,
      // 安全：afterData 不写明文/hash
      description: `重置用户 #${id} 密码`,
      status: 1,
    });
    this.success(null, '密码已重置');
  } catch (e: any) {
    await this.service.audit.log({
      module: 'user', action: 'reset-password',
      bizType: 'user', bizId: id,
      beforeData,
      description: `尝试重置用户 #${id} 密码`,
      status: 0, failReason: e.message,
    });
    throw e;
  }
}
```

#### 审计

- module: `user`
- action: `reset-password`（**新增 audit action 词表**——加入 `app/service/audit.ts` 的 ACTIONS 常量）
- 不记录新密码（明文/hash 都不留痕）

### 2.3 接口 2：改用户状态 `PUT /api/admin/users/:id/status`

#### 请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `status` | number | 是 | 0=禁用 / 1=正常 |

#### 响应

```json
{ "code": 200, "message": "状态已更新", "data": { "id": 5, "status": 0, ...stripped } }
```

#### Service 签名

```typescript
async adminChangeStatus(adminId: number, targetUserId: number, status: 0 | 1): Promise<any>
```

#### 实现要点

```typescript
async adminChangeStatus(adminId: number, targetUserId: number, status: 0 | 1) {
  if (![0, 1].includes(status)) this.ctx.throw(422, 'status must be 0 or 1');

  const user = await this.ctx.model.User.findByPk(targetUserId);
  if (!user) this.ctx.throw(404, '用户不存在');

  // 防止 admin 自禁
  if (adminId === targetUserId && status === 0) {
    this.ctx.throw(400, '不能禁用自己的账户');
  }

  await (user as any).update({ status });
  await this.clearCache(`${this.CACHE_PREFIX}${targetUserId}`);
  const result = (user as any).toJSON();
  delete result.passwordHash;
  return result;
}
```

#### 审计

- module: `user`
- action: `update`（复用现有 update action）
- description: `禁用用户 #5` / `启用用户 #5`
- beforeData/afterData：`{ id, status }` 子集

```json
    "page": 1,
    "pageSize": 20,
    "rows": [
      {
        "id": 1, "userId": 5, "type": "bug", "content": "...",

      }
    ]
  }
}
```

⚠️ **关键差异**：feedback list 返回 `data.rows`（与 user 的 `data.list` 不同）。前端需分别处理。

#### `GET /api/admin/feedbacks/:id` - 反馈详情

响应额外包含 `replier`（同 user 子集字段）。

#### `POST /api/admin/feedbacks/:id/reply` - 回复

```json
// 请求体
{ "replyContent": "已修复，感谢反馈" }
```

⚠️ Service 严格状态机：仅 status 为 0/1 时允许回复，否则抛 409。前端需在 UI 上禁用回复按钮（status >= 2 时）。

#### `PUT /api/admin/feedbacks/:id` - 状态切换

```json
// 请求体
{ "status": 1 }
```

状态转移白名单（service 层强校验）：

| from | to 允许集 |
|---|---|
| 0 | 1, 3 |
| 1 | 0, 3 |
| 2 | 1（重新打开） |
| 3 | 1（重新打开） |
| from === to | 幂等允许 |

⚠️ **特别注意**：`0/1 → 2` 被 reply 独占，**前端"已回复"切换必须走 reply 接口**，不能用 PUT status=2（service 会抛 422）。

## 3. 数据库迁移 `009_add_user_admin_actions.sql`

### 3.1 范围

- 新增 2 个权限码：`user:device:list` / `user:address:list`
- 关联 super_admin

### 3.2 SQL 全文

```sql
-- ============================================================
-- 009 Spec-C2a 管理端用户行为权限补全
-- ============================================================
-- 依赖：006_add_rbac_init.sql 已建表 + 已建 user 顶级菜单
-- 新增：user:device:list / user:address:list 两条 type=4 权限
-- 影响：super_admin 自动具备
-- 回滚：见 § 3.3
-- ============================================================

-- ------------------------------------------------------------
-- 1. 新增权限（type=4 API 级）
-- ------------------------------------------------------------
INSERT INTO `permissions`
  (`code`, `name`, `type`, `module`, `platform`, `path`, `method`, `parent_id`, `sort`)
SELECT 'user:device:list', '查看用户设备列表', 4, 'user', 'admin',
       '/api/admin/users/:id/devices', 'GET',
       (SELECT id FROM (SELECT id FROM `permissions` WHERE code = 'user') t), 110
WHERE NOT EXISTS (SELECT 1 FROM `permissions` WHERE code = 'user:device:list')
UNION ALL
SELECT 'user:address:list', '查看用户地址列表', 4, 'user', 'admin',
       '/api/admin/users/:id/addresses', 'GET',
       (SELECT id FROM (SELECT id FROM `permissions` WHERE code = 'user') t), 120
WHERE NOT EXISTS (SELECT 1 FROM `permissions` WHERE code = 'user:address:list');

-- ------------------------------------------------------------
-- 2. 关联 super_admin（确保超管自动具备新权限）
-- ------------------------------------------------------------
INSERT INTO `role_permissions` (`role_id`, `permission_id`)
SELECT
  (SELECT id FROM `roles` WHERE code = 'super_admin'),
  p.id
FROM `permissions` p
WHERE p.code IN ('user:device:list', 'user:address:list')
  AND NOT EXISTS (
    SELECT 1 FROM `role_permissions` rp
    WHERE rp.role_id = (SELECT id FROM `roles` WHERE code = 'super_admin')
      AND rp.permission_id = p.id
  );

-- ------------------------------------------------------------
-- 3. 校验
-- ------------------------------------------------------------
SELECT '新增权限' AS step, code, name, path, method
FROM `permissions`
WHERE code IN ('user:device:list', 'user:address:list');

SELECT 'super_admin 关联' AS step, COUNT(*) AS cnt
FROM `role_permissions` rp
JOIN `permissions` p ON p.id = rp.permission_id
WHERE rp.role_id = (SELECT id FROM `roles` WHERE code = 'super_admin')
  AND p.code IN ('user:device:list', 'user:address:list');
-- 预期 cnt=2
```

### 3.3 回滚 SQL

```sql
DELETE FROM `role_permissions`
WHERE permission_id IN (
  SELECT id FROM `permissions` WHERE code IN ('user:device:list', 'user:address:list')
);
DELETE FROM `permissions` WHERE code IN ('user:device:list', 'user:address:list');
```

#### 5.2.4 List 流程图

```typescript
export function formatDateTime(v?: string | null): string {
  if (!v) return '-';
  const d = new Date(v);
  if (isNaN(d.getTime())) return v;
  const pad = (n: number) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())} ${pad(d.getHours())}:${pad(d.getMinutes())}`;
}
```

## 9. 风险与边界 / 验收清单

### 9.1 风险与边界

| 风险 | 等级 | 缓解 |
|---|---|---|
| 用户列表接口路径 `/api/users` 与 init.sql 中权限码 path 字段（`/api/admin/users`）不一致 | 中 | C2a 不修，继续路径不一致；写 README 备注；独立"路径统一 spec"做 |
| feedback 状态机白名单后端可能未来调整 | 低 | 前端 utils 抽离常量，后端调整后同步前端 |
| reset-password 未走严格密码强度校验 | 中 | controller validate min:8 max:50；不强制复杂度（与 C 端 changePassword 行为一致） |
| admin 跨用户查看设备/地址泄漏隐私 | 中 | RBAC 控制（`user:device:list` / `user:address:list`），仅 super_admin 默认具备 |
| 自身保护逻辑前后端两层 | 低 | service 层硬校验（不能禁自己 / 不能改自己密码），前端 UI 兜底（disabled） |
| feedback list `data.rows` vs user list `data.list` 结构差异 | 低 | service.ts 内文档清晰约定，列表组件分别处理 |
| Devices/Addresses Tab 大量历史数据无分页 | 低 | C2a 内不分页（admin 单用户场景数据量有限）；后续如需要可独立加分页 |
| 列表内联 status Select 与抽屉 status Select 重复实现 | 低 | 抽离 `<StatusChanger>` 组件复用 |
| Drawer Tab 切换重复请求 | 低 | 各 Tab 内部 useEffect 监听 userId 变化，单一 userId 下只请求一次 |
| 测试 ts-jest + TS 5.4 兼容性 | 中 | 沿用 C1 方案，所有测试文件用 `.tsx` 扩展名走 babel-jest |
