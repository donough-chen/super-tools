## 一、需求概览

### 1.1 需求背景

项目前端代码（`super-tools-web/packages/h5/micro-tools`）已经包含大量小工具页面，
目前工具清单以**静态 JS 文件** `super-tool-node/test1.js` 的形式硬编码（11 个分类、**233 个工具**），
缺少后端管理能力：
- 无法动态上下架工具
- 无法为工具打"会员专属 / 特色功能"标识以驱动付费转化
- 没有分类和工具的 CRUD 后台
- H5 端无法从接口拉取运营维护的数据

本模块在既有会员等级体系（`user_members` / `member_levels` / `paid_plans`）之上，
新增**工具分类**与**工具**两张表，补齐后台管理与 H5 数据接口，
并与现有会员权限体系打通（会员专属工具凭 `required_level_code` + `require_paid` 判定）。

### 1.2 需求范围

| IN（本期实现） | OUT（后续迭代） |
|---------------|----------------|
| 分类 CRUD（管理端） | 工具使用次数统计 |
| 工具 CRUD（管理端） | 用户收藏/历史记录 |
| 批量发布/下架 | 工具评分评论 |
| 会员专属 & 特色功能标识 | 工具智能推荐 |
| H5 端首页聚合 / 分页查询 | 工具 A/B 实验开关 |
| H5 端特色/会员专属 Tab | 工具个性化排序 |
| 工具使用前权限校验 | 跨端数据同步（小程序端） |
| 233 工具 + 11 分类数据初始化 | 数据后台埋点分析 |

### 1.3 设计原则

1. **与现有规范零偏离**：完全沿用 `BaseController` / `BaseService` / `app.model.define` 模式、`underscored` 命名、迁移文件编号规则、路由注册风格
2. **浏览 ≠ 使用，权限懒校验**：H5 列表接口对所有用户开放，用户点击跳转时才调用 `checkAccess` 做权限校验，降低接口耦合
3. **正交字段设计**：`is_feature`（运营维度）与 `required_level_code`/`require_paid`（权限维度）解耦，允许一个工具同时出现在两个 Tab
4. **扩展而非修改**：不改 `users` 表和 `user_members` 表，通过新表 + 外键实现
5. **迁移即初始化**：233 个工具作为 migration 种子数据一次性写入，保证环境可复现，不依赖运行时任务

## 三、数据库详细设计

### 3.1 表结构总览

| 表名 | 说明 | 记录数（种子） |
|------|------|------|
| `tool_categories` | 工具分类（静态，后台维护） | 11 |
| `tools` | 工具定义（运营维护） | 233 |

### 3.2 `tool_categories` — 工具分类表

```sql
CREATE TABLE IF NOT EXISTS `tool_categories` (
  `id`           INT UNSIGNED     NOT NULL AUTO_INCREMENT,
  `code`         VARCHAR(30)      NOT NULL                 COMMENT '分类编码（DAILY/DOCUMENT/...）',
  `name`         VARCHAR(50)      NOT NULL                 COMMENT '分类名称',
  `icon`         VARCHAR(500)     DEFAULT NULL             COMMENT '分类图标 URL',
  `description`  VARCHAR(500)     DEFAULT NULL             COMMENT '分类描述',
  `sort`         INT              NOT NULL DEFAULT 0       COMMENT '排序（越小越前）',
  `status`       TINYINT UNSIGNED NOT NULL DEFAULT 1       COMMENT '状态:0禁用,1启用',
  `created_at`   DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`   DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code`       (`code`),
  INDEX       `idx_status_sort` (`status`, `sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='工具分类表';
```

### 3.3 `tools` — 工具表

```sql
CREATE TABLE IF NOT EXISTS `tools` (
  `id`                   BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT,
  `code`                 VARCHAR(60)      NOT NULL                          COMMENT '工具编码（gold-price 等，与前端路由 slug 对齐）',
  `name`                 VARCHAR(80)      NOT NULL                          COMMENT '工具名称',
  `description`          VARCHAR(500)     NOT NULL DEFAULT ''               COMMENT '工具描述',
  `keyword`              VARCHAR(500)     NOT NULL DEFAULT ''               COMMENT '搜索关键字（管道分隔）',
  `category_id`          INT UNSIGNED     NOT NULL                          COMMENT '分类ID',
  `category_code`        VARCHAR(30)      NOT NULL                          COMMENT '分类编码（冗余，便于筛选）',
  `icon`                 VARCHAR(500)     NOT NULL DEFAULT ''               COMMENT '工具图标',
  `color`                VARCHAR(20)      NOT NULL DEFAULT ''               COMMENT '主题色（#HEX）',
  `path`                 VARCHAR(200)     NOT NULL DEFAULT ''               COMMENT '前端路由路径',
  `is_feature`           TINYINT UNSIGNED NOT NULL DEFAULT 0                COMMENT '是否特色功能:0否,1是',
  `required_level_code`  VARCHAR(30)      NOT NULL DEFAULT 'free'           COMMENT '最低成长等级要求',
  `require_paid`         TINYINT UNSIGNED NOT NULL DEFAULT 0                COMMENT '是否要求付费会员:0否,1是',
  `status`               TINYINT UNSIGNED NOT NULL DEFAULT 0                COMMENT '状态:0下架,1已发布',
  `sort`                 INT              NOT NULL DEFAULT 0                COMMENT '同分类内排序',
  `created_at`           DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`           DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code`                    (`code`),
  INDEX       `idx_status`                (`status`),
  INDEX       `idx_cat_status_sort`       (`category_code`, `status`, `sort`),
  INDEX       `idx_feature_status`        (`is_feature`, `status`),
  INDEX       `idx_required_level`        (`required_level_code`),
  INDEX       `idx_require_paid`          (`require_paid`),
  CONSTRAINT `fk_tool_category` FOREIGN KEY (`category_id`)
    REFERENCES `tool_categories` (`id`) ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='工具表';
```

**索引解析**：

| 索引 | 用于 |
|------|------|
| `uk_code` | H5 端 `GET /api/tools/:code/access` 查询 |
| `idx_status` | H5 首页聚合模式：`WHERE status=1` 全量拉取后内存分组 |
| `idx_cat_status_sort` | H5 分页模式：`WHERE category_code=? AND status=1 ORDER BY sort` |
| `idx_feature_status` | 特色 Tab：`WHERE is_feature=1 AND status=1` |
| `idx_required_level` / `idx_require_paid` | 会员 Tab：`WHERE status=1 AND (required_level_code!='free' OR require_paid=1)` |

**外键策略**：`ON DELETE RESTRICT` — 禁止删除尚有工具的分类。由 Service 层在 `deleteCategory` 前先查旗下工具数，给出友好报错而非依赖数据库抛异常。

### 3.4 状态字段语义

| 字段 | 值 | 含义 |
|------|-----|------|
| `tool_categories.status` | 0 | 分类禁用（H5 端不展示，管理端可见） |
|  | 1 | 分类启用 |
| `tools.status` | 0 | **未发布 / 已下架**（H5 端不可见；管理端可见并可重新发布） |
|  | 1 | **已发布**（H5 端可浏览；受 `required_level_code` + `require_paid` 使用时校验） |

## 四、权限模型与校验流程

### 4.1 权限字段语义

工具表上的权限相关字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `required_level_code` | VARCHAR(30) | 最低成长等级编码，取值：`free / silver / gold / diamond / black` |
| `require_paid` | TINYINT | 是否额外要求付费会员：0 否 / 1 是 |

**判定逻辑**：工具「可使用」需同时满足
1. `user_members.level_code` 对应 `member_levels.level` ≥ `required_level_code` 对应 `member_levels.level`
2. 若 `require_paid = 1`，则 `user_members.is_paid = 1` 且 `paid_expire_at > now()`（或 `paid_expire_at IS NULL` 表示终身）

**"会员专属"的定义**：`required_level_code != 'free' OR require_paid = 1`。用于 H5 会员 Tab 筛选。

### 4.2 懒校验流程

根据需求 "工具列表全部用户都能浏览，当用户点击跳转后使用时才进行校验"：

```
┌────────────────────────────────────────────┐
│ 阶段 1：浏览                                 │
│ H5 列表接口（home/feature/member）            │
│ - 不挂 auth 中间件                            │
│ - 返回字段含 isFeature/requiredLevelCode     │
│   /requirePaid，前端可打角标                   │
└───────────────────┬────────────────────────┘
                    │
┌───────────────────▼────────────────────────┐
│ 阶段 2：点击跳转 - 前置校验                    │
│ GET /api/tools/:code/access  (auth required)│
│                                              │
│ 1. auth 中间件 → 校验登录                     │
│    未登录 → 401                              │
│                                              │
│ 2. Service.checkToolAccess:                  │
│    ① 查 tools 获取 required_level_code       │
│       / require_paid / status                │
│    ② status=0 → 400 "工具已下架"             │
│    ③ 查 user_members + include MemberLevel   │
│    ④ 比较 level 数值                          │
│    ⑤ 校验 is_paid / paid_expire_at           │
│                                              │
│ 3. 返回:                                     │
│    { allowed: true }                         │
│    或                                        │
│    { allowed: false,                         │
│      reason: 'need_level'|'need_paid'|       │
│              'paid_expired',                 │
│      required: {                             │
│        levelCode, levelName, requirePaid     │
│      }                                       │
│    }                                         │
└───────────────────┬────────────────────────┘
                    │
┌───────────────────▼────────────────────────┐
│ 阶段 3：前端决策                              │
│ allowed=true  → 跳转 tool.path               │
│ allowed=false → 按 reason 展示升级/开通引导   │
└────────────────────────────────────────────┘
```

### 4.3 会员等级数值比较

由于 `required_level_code` 存的是字符串，比较时需换算为数值。在 `checkToolAccess` 中一次性查出全部 `member_levels`（或缓存）：

```ts
// 伪代码
const levelMap = await getLevelMap();  // { free:0, silver:1, gold:2, diamond:3, black:4 }
const required = levelMap[tool.requiredLevelCode] ?? 0;
const owned    = levelMap[userMember.levelCode]   ?? 0;
if (owned < required) return { allowed: false, reason: 'need_level', required: {...} };
```

`levelMap` 的获取复用 `MemberService.getLevelList()`（已有 Redis 缓存 600s）。

## 五、API 接口详细设计

### 5.1 H5 端接口（4 个）

#### 5.1.1 `GET /api/tools/home` — 首页聚合/分页

**鉴权**：无

**Query 参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `categoryCode` | string | 否 | 分类编码。传值 → 切换到分页模式 |
| `keyword` | string | 否 | 关键字搜索（模糊匹配 `name/description/keyword`）。传值 → 切换到分页模式 |
| `page` | int | 否（默认 1） | 分页页码（仅分页模式生效） |
| `pageSize` | int | 否（默认 20，最大 100） | 每页条数 |

**触发模式**：当 `categoryCode` 与 `keyword` **均未传**时走**聚合模式**；**任一**传入时走**分页模式**。

**聚合模式响应**（`mode: "aggregate"`）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "mode": "aggregate",
    "categories": [
      {
        "id": 1,
        "code": "DAILY",
        "name": "日常应用",
        "icon": null,
        "description": null,
        "sort": 0,
        "tools": [
          {
            "id": 101,
            "code": "gold-price",
            "name": "今日黄金价格",
            "description": "实时黄金价格查询",
            "keyword": "黄金|价格|行情|投资",
            "categoryCode": "DAILY",
            "icon": "/assets/imgs/price_change_...svg",
            "color": "#F39C12",
            "path": "/gold-price",
            "isFeature": 0,
            "requiredLevelCode": "free",
            "requirePaid": 0,
            "sort": 1
          }
          // ... 该分类下全部已发布工具
        ]
      }
      // ... 11 个分类
    ]
  },
  "timestamp": 1746527280000
}
```

**分页模式响应**（`mode: "paginated"`）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "mode": "paginated",
    "categories": [
      { "id": 1, "code": "DAILY", "name": "日常应用", "icon": null, "sort": 0 }
      // ... 11 个分类（无 tools 字段）
    ],
    "tools": {
      "list": [ /* Tool 对象数组 */ ],
      "total": 30,
      "page": 1,
      "pageSize": 20,
      "totalPages": 2
    }
  },
  "timestamp": 1746527280000
}
```

**业务规则**：
- 仅返回 `status=1` 的工具、`status=1` 的分类
- 聚合模式不分页，不截断，按 `sort ASC, id ASC` 排序
- 分页模式 `categoryCode` 不合法时返回空列表（不报错）
- 聚合模式走 Redis 缓存 `tool:home:aggregate`（TTL 300s），分页模式不缓存

#### 5.1.2 `GET /api/tools/feature` — 特色功能 Tab

**鉴权**：无

**Query**：`page` / `pageSize`（与 `home` 相同）

**响应**：标准 `paginated` 格式（见 `BaseController.paginated`）

**筛选条件**：`WHERE is_feature = 1 AND status = 1` ORDER BY `sort ASC, id ASC`

#### 5.1.3 `GET /api/tools/member` — 会员专属 Tab

**鉴权**：无

**Query**：`page` / `pageSize`

**筛选条件**：`WHERE status = 1 AND (required_level_code != 'free' OR require_paid = 1)` ORDER BY `sort ASC, id ASC`

**备注**：此 Tab 与特色 Tab **不互斥**，同一工具若 `is_feature=1` 且 `required_level_code='silver'` 则在两个 Tab 都会出现。

#### 5.1.4 `GET /api/tools/:code/access` — 使用前权限校验

**鉴权**：需登录（`auth`）

**Path**：`code` — 工具编码

**响应 (allowed=true)**：

```json
{
  "code": 200, "message": "success",
  "data": {
    "allowed": true,
    "tool": {
      "code": "ai-chat",
      "name": "AI 对话",
      "path": "/ai-chat"
    }
  }
}
```

**响应 (allowed=false)**：

```json
{
  "code": 200, "message": "success",
  "data": {
    "allowed": false,
    "reason": "need_level",
    "required": {
      "levelCode": "silver",
      "levelName": "银牌会员",
      "requirePaid": 0
    },
    "current": {
      "levelCode": "free",
      "isPaid": false
    }
  }
}
```

**`reason` 枚举**：

| 值 | 含义 |
|----|------|
| `need_level` | 用户当前等级不足 |
| `need_paid` | 工具要求付费，用户未付费 |
| `paid_expired` | 用户曾付费但已过期 |

**错误响应**：

| HTTP | 场景 |
|------|------|
| 401 | 未登录 |
| 404 | 工具不存在 |
| 400 | 工具已下架（`status=0`），`message: "工具已下架"` |

### 5.2 接口安全与限流

- H5 端三个列表接口无鉴权但访问频率依赖接入层限流（不在本模块处理）
- `checkAccess` 接口受 `auth` 保护，每次实际 1 次 MySQL + 可能的 Redis 查询，性能可控

## 六、Service 层核心逻辑

### 6.1 `ToolService` 方法一览（`app/service/tool.ts`）

```ts
class ToolService extends BaseService {
  // ============ H5 端 ============
  async getHomeData(query: { categoryCode?: string; keyword?: string; page?: number; pageSize?: number }): Promise<HomeResult>;
  async getFeatureTools(pagination: PaginationOptions): Promise<PaginationResult<Tool>>;
  async getMemberTools(pagination: PaginationOptions): Promise<PaginationResult<Tool>>;
  async checkToolAccess(userId: number, toolCode: string): Promise<AccessResult>;

  // ============ 管理端 - 分类 ============
  async listCategoriesAdmin(query: AdminCategoryQuery): Promise<PaginationResult<ToolCategory>>;
  async createCategory(data: CreateCategoryDto): Promise<ToolCategory>;
  async updateCategory(id: number, data: UpdateCategoryDto): Promise<ToolCategory>;
  async deleteCategory(id: number): Promise<void>;

  // ============ 管理端 - 工具 ============
  async listToolsAdmin(query: AdminToolQuery): Promise<PaginationResult<Tool>>;
  async getToolById(id: number): Promise<Tool>;
  async createTool(data: CreateToolDto): Promise<Tool>;
  async updateTool(id: number, data: UpdateToolDto): Promise<Tool>;
  async deleteTool(id: number): Promise<void>;
  async batchPublish(ids: number[], status: 0 | 1): Promise<{ affected: number }>;
}
```

### 6.2 核心方法详细逻辑

#### 6.2.1 `getHomeData`（双模式核心）

```
1. 若 categoryCode 和 keyword 都未传 → 走聚合模式：
   a. 尝试 Redis 读 tool:home:aggregate
   b. 未命中：
      - SELECT 全量启用分类
      - SELECT 全量 status=1 工具
      - 内存按 category_code 分组
      - 写缓存 300s
2. 否则走分页模式：
   a. SELECT 全量启用分类（走 getOrSetCache tool:categories:all）
   b. 组装 where: { status: 1 }
      - categoryCode 传入 → where.category_code = categoryCode
      - keyword 传入 → where[Op.or] = [name/description/keyword LIKE %x%]
   c. this.paginate(ctx.model.Tool, { where, order: [['sort','ASC'],['id','ASC']] }, pagination)
3. 返回 { mode, categories, tools? } 结构
```

#### 6.2.2 `checkToolAccess`

```
1. 查 tools WHERE code = :code
   - 不存在 → 404
   - status = 0 → 400 "工具已下架"
2. 查 user_members WHERE user_id = :userId include MemberLevel
   - 不存在 → 404 "会员记录不存在"（注册时应已 initMember）
3. 免费工具快速通道：
   若 required_level_code = 'free' && require_paid = 0 → { allowed: true }
4. 获取 levelMap（复用 MemberService.getLevelList → Redis 缓存）
5. 等级判定：
   if levelMap[owned] < levelMap[required]
       → { allowed: false, reason: 'need_level', required, current }
6. 付费判定：
   if require_paid = 1:
      if !isPaid → { allowed: false, reason: 'need_paid', required, current }
      if paid_expire_at && paid_expire_at <= now()
          → { allowed: false, reason: 'paid_expired', required, current }
7. 全部通过 → { allowed: true, tool: { code, name, path } }
```

#### 6.2.3 `batchPublish`

```
1. 参数校验：ids 必须为非空数组，status ∈ {0, 1}
2. 单条 UPDATE：
   this.ctx.model.Tool.update(
     { status },
     { where: { id: { [Op.in]: ids } } }
   )
3. 清缓存：clearCache('tool:home:*')
4. 返回 { affected: 受影响行数 }
```

#### 6.2.4 `deleteCategory`

```
1. 查 count of tools WHERE category_id = :id
2. > 0 → 抛 400 "该分类下尚有 N 个工具，请先移除或删除后再操作"
3. 执行删除
4. 清缓存：clearCache('tool:*')
```

### 6.3 写操作的缓存治理

**统一规则**：**任意写操作后均调用 `clearCache('tool:*')` 清除全部工具相关缓存**。

| 写操作 | 清除范围 |
|--------|----------|
| 分类 create/update/delete | `tool:*` |
| 工具 create/update/delete | `tool:*` |
| 工具 batchPublish | `tool:*` |
| 工具 updateTool（含 is_feature 或权限字段） | `tool:*` |

理由：管理端写操作低频（人工点击），统一清理无性能风险；避免"精准清理"带来的边界判断漏洞（如修改分类 name 后，聚合缓存中的分类名未同步）。

## 七、缓存策略

| Key | 值 | TTL | 写入时机 | 失效时机 |
|-----|-----|-----|---------|----------|
| `tool:categories:all` | 全量启用分类 JSON | 600s | 首次查询 | 分类写操作 |
| `tool:home:aggregate` | 聚合首页全量数据 | 300s | 首次查询 | 分类/工具写操作 |
| `member:levels:all` | 全量等级（MemberService 已有） | 600s | 首次查询 | 等级写操作 |

**注意**：
- 分页模式不缓存（参数多变、ROI 低）
- `checkToolAccess` 不直接缓存工具数据（每次单点查询成本已很低）
- Redis 不可用时全部降级到 MySQL，遵循 `BaseService.getOrSetCache` 的现有容错模式

### 9.2 管理端接口详细

#### 9.2.1 `GET /api/admin/tool-categories`

Query 参数（复用 `BaseController.getPagination`）：
- `page` / `pageSize`
- `status` (0/1，可选)
- `keyword` (可选，模糊匹配 `name/code`)

响应：标准 `paginated` 格式，每项含工具数量 `toolCount`（通过 `COUNT` 子查询或 `hasMany.count`）。

#### 9.2.2 `POST /api/admin/tool-categories`

Body (validate 规则)：
```ts
{
  code: { type: 'string', required: true, min: 2, max: 30 },
  name: { type: 'string', required: true, min: 1, max: 50 },
  icon: { type: 'string', required: false, max: 500 },
  description: { type: 'string', required: false, max: 500 },
  sort: { type: 'number', required: false },
  status: { type: 'enum', values: [0, 1], required: false, default: 1 },
}
```

冲突处理：`code` 唯一，重复 → 409 "分类编码已存在"。

#### 9.2.3 `GET /api/admin/tools`

Query：
- `page` / `pageSize`
- `categoryCode` (可选)
- `status` (0/1，可选)
- `isFeature` (0/1，可选)
- `requiredLevelCode` (可选)
- `requirePaid` (0/1，可选)
- `keyword` (可选，匹配 `code/name/description/keyword`)

响应：标准 `paginated`，每项 include `category`。

#### 9.2.4 `POST /api/admin/tools`

Body (validate)：
```ts
{
  code: { type: 'string', required: true, min: 2, max: 60 },
  name: { type: 'string', required: true, min: 1, max: 80 },
  description: { type: 'string', required: false, max: 500 },
  keyword: { type: 'string', required: false, max: 500 },
  categoryId: { type: 'number', required: true },
  icon: { type: 'string', required: false, max: 500 },
  color: { type: 'string', required: false, max: 20 },
  path: { type: 'string', required: true, min: 1, max: 200 },
  isFeature: { type: 'enum', values: [0, 1], required: false, default: 0 },
  requiredLevelCode: { type: 'enum', values: ['free','silver','gold','diamond','black'], required: false, default: 'free' },
  requirePaid: { type: 'enum', values: [0, 1], required: false, default: 0 },
  status: { type: 'enum', values: [0, 1], required: false, default: 0 },
  sort: { type: 'number', required: false, default: 0 },
}
```

`categoryCode` 由 Service 根据 `categoryId` 自动填充（保证冗余字段一致）。

#### 9.2.5 `PUT /api/admin/tools/batch-publish`

Body：
```ts
{
  ids: { type: 'array', itemType: 'number', required: true, min: 1, max: 500 },
  status: { type: 'enum', values: [0, 1], required: true }
}
```

响应：
```json
{
  "code": 200,
  "message": "批量处理成功",
  "data": { "affected": 12 }
}
```

业务规则：
- `status=1` 语义为发布，`status=0` 语义为下架
- 单次最多 500 个 id（防止恶意请求）
- 返回实际受影响行数（可能小于 `ids.length` —— 部分 id 不存在或状态已一致）
