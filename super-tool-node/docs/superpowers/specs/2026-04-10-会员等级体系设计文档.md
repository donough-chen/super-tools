## 一、需求概览

### 1.1 需求背景

当前系统缺少完整的会员等级体系。`users.user_type` 原为权限类型区分字段（已于 v2.9 废弃，权限统一走 RBAC），不具备会员等级差异化服务能力。评估报告中将会员体系列为 **P2 业务扩展**，从登录注册改进需求中独立拆分。

### 1.2 设计方案选择

经过 brainstorming 评估，选择 **方案 B「单表融合」**：

```
┌──────────────────────────────────────────────────────┐
│                    用户 (users)                        │
│                        │                              │
│  ┌─────────────────────▼──────────────────────────┐  │
│  │           user_members (用户会员状态)             │  │
│  │  ┌──────────────┐  ┌──────────────────────┐    │  │
│  │  │ 成长等级模块   │  │ 付费会员模块           │    │  │
│  │  │ · growth_value│  │ · is_paid            │    │  │
│  │  │ · total_points│  │ · paid_plan_code     │    │  │
│  │  │ · level_id    │  │ · paid_expire_at     │    │  │
│  │  └──────────────┘  └──────────────────────┘    │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  ┌──────────────┐  ┌──────────┐  ┌────────────────┐  │
│  │member_levels │  │paid_plans│  │  points_logs   │  │
│  │(成长等级定义) │  │(付费套餐) │  │  (积分流水)    │  │
│  └──────────────┘  └──────────┘  └────────────────┘  │
└──────────────────────────────────────────────────────┘
```

**选择理由**：
1. 表精简（4 张），查询只需 1 次 JOIN
2. 兼容评估报告已有的 `member_levels` / `user_members` / `points_logs` 表设计
3. 当前阶段无支付系统，`paid_plans` 暂时只做定义，不依赖支付
4. 后续可无缝添加 `subscription_orders` 表升级为完整版

### 1.3 需求范围

| IN（本期实现） | OUT（后续迭代） |
|---------------|----------------|
| 成长等级定义（5 级） | 支付购买会员 |
| 付费套餐定义 | 自动扣费/续费 |
| 用户会员状态管理 | 积分商城 |
| 积分获取与消耗 | 等级降级策略 |
| 等级自动升级 | 积分过期回收 |
| 权益查询聚合 | 第三方会员体系对接 |
| 管理后台 CRUD | 会员专属活动系统 |

### 1.4 核心设计原则

1. **会员与权限分离**：`user_members.level_code` 控制服务差异化（折扣/功能），`roles` 控制系统权限，两套体系独立演进
2. **权益 JSON 化**：等级权益和付费权益均用 JSON 存储，支持灵活配置和无缝扩展
3. **最终一致性**：积分变动 → 成长值更新 → 等级升级，在同一事务中完成
4. **扩展而非修改**：不修改 `users` 主表，通过 `user_members` 1:1 扩展实现

## 二、体系架构设计

### 2.1 双轨并行模型

```
                    ┌─────────────────────┐
                    │      用户会员体系     │
                    └──────────┬──────────┘
                   ┌───────────┴───────────┐
              ┌────▼─────┐           ┌─────▼────┐
              │ 成长等级轨 │           │ 付费会员轨 │
              │ (免费升级) │           │ (付费订阅) │
              └────┬─────┘           └─────┬────┘
                   │                       │
        ┌──────────┼──────────┐            │
   ┌────▼───┐ ┌────▼───┐ ┌───▼────┐  ┌────▼─────┐
   │ 普通用户 │ │ 银牌    │ │ 金牌   │  │ 月卡/年卡 │
   │ Lv.0   │ │ Lv.1   │ │ Lv.2   │  │ 付费增益  │
   └────────┘ └────────┘ └────────┘  └──────────┘
                   │                       │
                   └───────────┬───────────┘
                          ┌────▼────┐
                          │ 权益聚合 │
                          │ (取并集) │
                          └─────────┘
```

**规则**：
- 成长等级通过**积分/成长值**自然升级，永久有效
- 付费会员通过**购买套餐**开通，有到期时间
- 最终权益 = 成长等级权益 **∪** 付费会员权益（取两者的并集，冲突时取更优值）

### 2.2 等级升级流程

```
用户行为（登录/消费/活动）
        │
        ▼
  ┌──────────────┐
  │ 积分流水记录   │  ← points_logs
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │ 更新积分余额   │  ← user_members.points + total_points
  │ 更新成长值     │  ← user_members.growth_value
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐     ┌──────────────┐
  │ 检查升级条件   │────>│ member_levels │
  └──────┬───────┘     │ (等级定义表)   │
    ┌────┴────┐        └──────────────┘
    │         │
 达标      未达标
    │         │
    ▼         ▼
 升级等级   保持现状
```

## 三、数据库详细设计

### 3.1 新增表一览

| 序号 | 表名 | 说明 | 类型 | 与 users 关系 |
|------|------|------|------|--------------|
| 1 | `member_levels` | 成长等级定义表 | 配置表 | 无直接关联 |
| 2 | `paid_plans` | 付费套餐定义表 | 配置表 | 无直接关联 |
| 3 | `user_members` | 用户会员状态表 | 业务表 | 1:1 |
| 4 | `points_logs` | 积分流水表 | 日志表 | 1:N |

### 3.2 DDL 迁移脚本

```sql
-- ============================================================
-- 迁移脚本: 003_add_member_system.sql
-- 版本: 2.2.0
-- 创建时间: 2026-04-10
-- 说明: 新增会员等级体系（成长等级 + 付费会员 + 积分流水）
-- 设计方案: 方案 B「单表融合」
-- ============================================================

USE `superadmin_db`;

SET NAMES utf8mb4;
SET FOREIGN_KEY_CHECKS = 0;


-- ------------------------------------------------------------
-- 1. 成长等级定义表
-- 策略: 静态配置表，后台管理维护
-- 预设: 5 级（普通 → 银牌 → 金牌 → 钻石 → 黑金）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `member_levels` (
  `id`              INT UNSIGNED      NOT NULL AUTO_INCREMENT,
  `name`            VARCHAR(50)       NOT NULL COMMENT '等级名称（普通会员/银牌/金牌/钻石/黑金）',
  `code`            VARCHAR(30)       NOT NULL COMMENT '等级编码（free/silver/gold/diamond/black）',
  `level`           TINYINT UNSIGNED  NOT NULL COMMENT '等级数值（0-9，越大越高）',
  `icon`            VARCHAR(500)      DEFAULT NULL COMMENT '等级图标 URL',
  `color`           VARCHAR(20)       DEFAULT NULL COMMENT '等级主题色（#HEX）',
  -- 升级条件（满足任一即可升级）
  `upgrade_points`  INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '升级所需累计积分',
  `upgrade_growth`  INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '升级所需成长值',
  `upgrade_consume` DECIMAL(10,2)     NOT NULL DEFAULT 0.00 COMMENT '升级所需累计消费金额',
  -- 等级权益（JSON 存储，灵活扩展）
  `benefits`        JSON              DEFAULT NULL COMMENT '成长等级权益配置',
  `description`     VARCHAR(500)      DEFAULT NULL COMMENT '等级描述',
  `sort`            INT               NOT NULL DEFAULT 0 COMMENT '排序（前端展示用）',
  `status`          TINYINT UNSIGNED  NOT NULL DEFAULT 1 COMMENT '状态:0禁用,1启用',
  `created_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code`  (`code`),
  UNIQUE KEY `uk_level` (`level`),
  INDEX `idx_status`    (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='成长等级定义表';


-- ------------------------------------------------------------
-- 2. 付费套餐定义表
-- 策略: 静态配置表，后台管理维护
-- 预设: 月卡 / 季卡 / 年卡 / 终身
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `paid_plans` (
  `id`              INT UNSIGNED      NOT NULL AUTO_INCREMENT,
  `name`            VARCHAR(50)       NOT NULL COMMENT '套餐名称（月度会员/季度会员/年度会员/终身会员）',
  `code`            VARCHAR(30)       NOT NULL COMMENT '套餐编码（monthly/quarterly/yearly/lifetime）',
  `duration_days`   INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '有效天数（0=终身）',
  `price`           DECIMAL(10,2)     NOT NULL DEFAULT 0.00 COMMENT '售价（元）',
  `original_price`  DECIMAL(10,2)     NOT NULL DEFAULT 0.00 COMMENT '原价（元，用于划线价展示）',
  -- 付费权益（JSON 存储，与成长权益格式一致，方便聚合）
  `benefits`        JSON              DEFAULT NULL COMMENT '付费会员额外权益配置',
  -- 赠送（购买套餐附赠积分/成长值）
  `gift_points`     INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '购买赠送积分',
  `gift_growth`     INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '购买赠送成长值',
  `description`     VARCHAR(500)      DEFAULT NULL COMMENT '套餐描述',
  `sort`            INT               NOT NULL DEFAULT 0 COMMENT '排序',
  `status`          TINYINT UNSIGNED  NOT NULL DEFAULT 1 COMMENT '状态:0下架,1上架',
  `created_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`),
  INDEX `idx_status`   (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='付费套餐定义表';


-- ------------------------------------------------------------
-- 3. 用户会员状态表（融合成长等级 + 付费会员）
-- 策略: 1:1 关联 users 表，一人一行
-- 关键: 同时承载成长等级字段和付费会员字段
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `user_members` (
  `id`              BIGINT UNSIGNED   NOT NULL AUTO_INCREMENT,
  `user_id`         BIGINT UNSIGNED   NOT NULL COMMENT '用户ID（唯一）',

  -- ========== 成长等级模块 ==========
  `level_id`        INT UNSIGNED      NOT NULL DEFAULT 1 COMMENT '当前成长等级ID',
  `level_code`      VARCHAR(30)       NOT NULL DEFAULT 'free' COMMENT '当前成长等级编码（冗余，查询优化）',
  `growth_value`    INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '成长值（用于等级升降计算）',
  `total_points`    INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '历史累计积分（只增不减，用于等级判定）',
  `total_consume`   DECIMAL(12,2)     NOT NULL DEFAULT 0.00 COMMENT '历史累计消费金额',

  -- ========== 积分模块 ==========
  `points`          INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '当前可用积分（可消耗）',

  -- ========== 付费会员模块 ==========
  `is_paid`         TINYINT(1)        NOT NULL DEFAULT 0 COMMENT '是否付费会员:0否,1是',
  `paid_plan_code`  VARCHAR(30)       DEFAULT NULL COMMENT '当前付费套餐编码',
  `paid_start_at`   DATETIME          DEFAULT NULL COMMENT '付费会员开始时间',
  `paid_expire_at`  DATETIME          DEFAULT NULL COMMENT '付费会员到期时间（NULL=终身）',

  -- ========== 等级有效期（可选，用于年度重置场景） ==========
  `level_expire_at` DATETIME          DEFAULT NULL COMMENT '成长等级有效期（NULL=永久）',

  `created_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_id`      (`user_id`),
  INDEX `idx_level_id`         (`level_id`),
  INDEX `idx_level_code`       (`level_code`),
  INDEX `idx_is_paid`          (`is_paid`),
  INDEX `idx_paid_expire`      (`paid_expire_at`),
  CONSTRAINT `fk_member_user` FOREIGN KEY (`user_id`)
    REFERENCES `users` (`id`) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户会员状态表';


-- ------------------------------------------------------------
-- 4. 积分流水表
-- 策略: 1:N 关联 users 表，只追加不修改
-- 注意: 高频写入表，建议按月归档或分区
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `points_logs` (
  `id`          BIGINT UNSIGNED   NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT UNSIGNED   NOT NULL COMMENT '用户ID',
  `type`        TINYINT UNSIGNED  NOT NULL COMMENT '类型:1获得,2消耗,3过期,4管理员调整',
  `source`      VARCHAR(50)       NOT NULL COMMENT '来源:register/daily_login/order/activity/exchange/admin/paid_gift',
  `points`      INT               NOT NULL COMMENT '积分变动（正数获得，负数消耗）',
  `balance`     INT UNSIGNED      NOT NULL COMMENT '变动后积分余额',
  `growth_delta`INT               NOT NULL DEFAULT 0 COMMENT '成长值变动（正数增长，负数扣减）',
  `biz_type`    VARCHAR(50)       DEFAULT NULL COMMENT '关联业务类型（如 order/activity/subscription）',
  `biz_id`      VARCHAR(64)       DEFAULT NULL COMMENT '关联业务ID',
  `remark`      VARCHAR(200)      DEFAULT NULL COMMENT '备注说明',
  `expire_at`   DATETIME          DEFAULT NULL COMMENT '积分过期时间（NULL=永不过期）',
  `created_at`  DATETIME          NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_user_id`    (`user_id`),
  INDEX `idx_type`       (`type`),
  INDEX `idx_source`     (`source`),
  INDEX `idx_biz`        (`biz_type`, `biz_id`),
  INDEX `idx_created_at` (`created_at`),
  INDEX `idx_expire_at`  (`expire_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='积分流水表';
```

### 4.4 权益聚合算法

```typescript
/**
 * 合并用户最终权益
 * 规则: 成长等级权益 + 付费会员权益 = 最终权益
 * 冲突处理: 数值取更优（更小折扣/更大额度），布尔取 OR
 */
function mergebenefits(
  levelBenefits: LevelBenefits,
  paidBenefits: PaidBenefits | null
): MergedBenefits {
  const merged = { ...levelBenefits };

  if (!paidBenefits) return merged;

  return {
    // 折扣叠加: 成长折扣 - 付费额外折扣
    discount: Math.max(0, levelBenefits.discount - (paidBenefits.discount_extra || 0)),
    // 签到积分: 使用成长等级的
    daily_sign_points: levelBenefits.daily_sign_points,
    // 设备数: 取更大值
    max_devices: Math.max(levelBenefits.max_devices, 20),
    // 布尔值: OR 合并
    ad_free: levelBenefits.ad_free || true,
    priority_support: levelBenefits.priority_support || true,
    exclusive_content: levelBenefits.exclusive_content || true,
    // 付费独有权益
    cloud_storage_gb: paidBenefits.cloud_storage_gb || 0,
    api_rate_limit: paidBenefits.api_rate_limit || 100,
    export_pdf: paidBenefits.export_pdf || false,
    custom_theme: paidBenefits.custom_theme || false,
    early_access: paidBenefits.early_access || false,
    founder_badge: paidBenefits.founder_badge || false,
    monthly_coupon: levelBenefits.monthly_coupon,
  };
}
```

## 五、积分体系设计

### 5.1 积分获取规则

| 行为 | 积分 | 成长值 | 频率限制 | source 值 |
|------|------|--------|---------|-----------|
| 注册 | 10 | 10 | 一次性 | `register` |
| 每日登录 | 1~10（随等级增长） | 1 | 每日 1 次 | `daily_login` |
| 订单消费 | 1积分/元 | 1成长值/元 | 无限制 | `order` |
| 运营活动 | 按活动配置 | 按活动配置 | 按活动规则 | `activity` |
| 购买付费会员 | 按套餐赠送 | 按套餐赠送 | 每次购买 | `paid_gift` |
| 管理员手动调整 | 自定义 | 自定义 | 无限制 | `admin` |

### 5.2 积分消耗规则

| 消耗方式 | 说明 | source 值 |
|---------|------|-----------|
| 积分兑换商品 | 扣减可用积分 | `exchange` |
| 积分抵扣订单金额 | 按比例抵扣 | `order` |
| 积分过期回收 | 定时任务自动处理 | `expire`（type=3） |

### 5.3 积分与成长值的关系

| 维度 | 积分（points） | 成长值（growth_value） |
|------|---------------|----------------------|
| 是否可消耗 | ✅ 可消耗（兑换/抵扣） | ❌ 只增不减 |
| 影响等级 | ❌ 不直接影响 | ✅ 是等级升级的核心指标 |
| 累计值 | `total_points`（只增不减） | `growth_value`（只增不减） |
| 当前值 | `points`（可变） | N/A |

> **关键区分**：`total_points` 是历史累计获得的总积分（用于部分等级判定场景），`growth_value` 是专门的成长维度，两者独立累加。积分消耗不影响 `total_points`，也不影响 `growth_value`。

### 7.2 核心流程：积分增加 + 自动升级

```typescript
/**
 * 增加积分和成长值（核心方法，其他积分操作都调用此方法）
 * 保证事务一致性：积分记录 + 余额更新 + 等级升级 在同一事务中
 */
async addPoints(params: {
  userId: number;
  points: number;           // 获得积分
  growthDelta: number;      // 获得成长值
  source: string;           // 来源
  bizType?: string;         // 业务类型
  bizId?: string;           // 业务ID
  remark?: string;          // 备注
}): Promise<AddPointsResult> {
  const { userId, points, growthDelta, source, bizType, bizId, remark } = params;

  return await this.ctx.model.transaction(async (t) => {
    // 1. 锁定用户会员记录（防并发）
    const member = await this.ctx.model.UserMember.findOne({
      where: { userId },
      lock: t.LOCK.UPDATE,
      transaction: t,
    });

    if (!member) throw new Error('会员记录不存在');

    // 2. 更新积分和成长值
    const newPoints = member.points + points;
    const newTotalPoints = member.totalPoints + points;
    const newGrowthValue = member.growthValue + growthDelta;

    await member.update({
      points: newPoints,
      totalPoints: newTotalPoints,
      growthValue: newGrowthValue,
    }, { transaction: t });

    // 3. 写入积分流水
    await this.ctx.model.PointsLog.create({
      userId,
      type: 1, // 获得
      source,
      points,
      balance: newPoints,
      growthDelta,
      bizType,
      bizId,
      remark,
    }, { transaction: t });

    // 4. 检查并执行等级升级
    const levelUpResult = await this.checkAndUpgrade(userId, newGrowthValue, t);

    return {
      pointsEarned: points,
      growthEarned: growthDelta,
      currentPoints: newPoints,
      currentGrowth: newGrowthValue,
      isLevelUp: levelUpResult.upgraded,
      newLevel: levelUpResult.newLevel,
    };
  });
}
```

### 7.3 核心流程：等级升级检查

```typescript
/**
 * 检查成长值是否满足升级条件，自动升级到对应等级
 * 支持跳级（如成长值从 400 直接到 2500，跳过银牌直升金牌）
 */
async checkAndUpgrade(
  userId: number,
  currentGrowth: number,
  transaction?: Transaction
): Promise<{ upgraded: boolean; newLevel?: MemberLevel }> {
  // 1. 获取所有启用的等级定义，按 level DESC 排序
  const levels = await this.ctx.model.MemberLevel.findAll({
    where: { status: 1 },
    order: [['level', 'DESC']],
  });

  // 2. 找到当前成长值对应的最高等级
  const targetLevel = levels.find(l => currentGrowth >= l.upgradeGrowth);
  if (!targetLevel) return { upgraded: false };

  // 3. 获取当前会员记录
  const member = await this.ctx.model.UserMember.findOne({
    where: { userId },
    ...(transaction ? { transaction } : {}),
  });

  // 4. 比较：如果目标等级 > 当前等级，执行升级
  if (targetLevel.level > member.levelId) {
    await member.update({
      levelId: targetLevel.id,
      levelCode: targetLevel.code,
    }, { ...(transaction ? { transaction } : {}) });

    // 5. 可选：发送升级通知
    // await this.ctx.service.notification.send(userId, 'level_up', { ... });

    return { upgraded: true, newLevel: targetLevel };
  }

  return { upgraded: false };
}
```
