# 添加新权限 SOP

> 适用场景：新增管理端 API、新增按钮级权限点、扩展业务模块

---

## 适用范围判断

如果你要做的事是 **以下之一**，按本文操作：

1. 新增一个管理端 API，需要做权限控制
2. 新增前端按钮，需要按角色显隐
3. 扩展七大模块之外的全新模块（如 `member`、`order`）

如果只是在已有模块下加一个 CRUD 路由，**直接套用现有同模块 code**（如 `category:list`），跳到第 4 步。

---

## 标准流程（5 步）

### 1. 想清楚 code 命名

按 `<module>[:<sub-module>]:<action>` 命名。  
完整规范见 [`docs/architecture/RBAC.md` § 4](../architecture/RBAC.md)。

```
✅  tool:export                    扩展 tool 模块的导出动作
✅  member:level:list              新模块 + 子模块
✅  system:role:batch-assign       已有子模块加新动作

❌  exportTool / tool.export / list-tool
```

### 2. 在 `permissions` 表新增记录

**裸库部署**：直接改 `database/init.sql` 的 `INSERT INTO permissions` 段。  
**存量库迁移**：新建迁移脚本 `database/<编号>_<描述>.sql`，编号顺延（007、008…）。

```sql
-- 例：给 tool 模块加导出权限
INSERT INTO `permissions`
  (`name`, `code`, `type`, `module`, `parent_id`, `path`, `method`, `sort`, `status`)
VALUES
  ('导出工具', 'tool:export', 4, 'tool',
   (SELECT id FROM (SELECT id FROM permissions WHERE code = 'tool:list') t),
   '/api/admin/tools/export', 'GET', 70, 1);
```

字段说明：

| 字段 | 取值 |
|---|---|
| `type` | `1` 目录 / `2` 菜单 / `3` 按钮 / `4` API |
| `module` | 必填，七大模块之一或新模块 |
| `parent_id` | 顶级 `0`，子节点用嵌套 `SELECT` 引用父 code |
| `path` / `method` | API 类型必填，纯文档作用 |

### 3. 给系统角色绑定（可选）

如果新权限要默认给某些系统角色，在同一脚本里追加 `role_permissions` 插入：

```sql
INSERT INTO `role_permissions` (`role_id`, `permission_id`)
SELECT r.id, p.id FROM roles r CROSS JOIN permissions p
WHERE r.code IN ('admin', 'operator')   -- 给 admin 和 operator
  AND p.code = 'tool:export'
ON DUPLICATE KEY UPDATE role_id = role_id;
```

> `super_admin` **不需要绑定**，中间件短路。

### 4. 在路由挂中间件

`app/router.ts`：

```ts
router.get(
  '/api/admin/tools/export',
  app.middleware.checkPermission('tool:export', app),
  controller.admin.tool.export,
);
```

**多权限 OR**：传数组 → `checkPermission(['tool:export', 'tool:batch-update'], app)`  
**多权限 AND**：链式挂多个中间件

### 5. 清缓存 + 验证

```bash
# 1. 跑迁移脚本
mysql -u <user> -p superadmin_db < database/007_add_tool_export.sql

# 2. 清 redis 缓存（否则旧缓存仍生效，最长延迟 1 小时）
redis-cli --scan --pattern "user:permissions:*" | xargs redis-cli DEL

# 3. 重启服务
pm2 restart super-tool-node

# 4. 写测试（参考 test/api/rbac.test.ts）
#   - super_admin 应 200
#   - 普通用户应 403
#   - 已绑权限的角色用户应 200
npm test -- test/api/<your-feature>.test.ts
```

## 检查清单

提 PR 前对照过一遍：

- [ ] code 命名符合 `<module>:<action>` 规范
- [ ] `permissions` 表已插入新记录，`module` 字段正确
- [ ] 默认应有该权限的系统角色（admin/operator/auditor）已绑定
- [ ] `app/router.ts` 已挂 `checkPermission`
- [ ] 迁移脚本可重复执行（用 `INSERT IGNORE` / `ON DUPLICATE KEY` 兜底）
- [ ] redis 缓存清理动作已写到迁移文档
- [ ] 至少有一条 super_admin 通过 / 普通用户 403 的测试用例
- [ ] 如果是新模块，已更新 `docs/architecture/RBAC.md` 的「七大业务模块」表

## 常见坑

### 坑 1：挂了 code 但所有 admin 都 403

**原因**：忘了给 `admin` 角色绑定，或 redis 缓存了旧的空权限列表。  
**解决**：检查 `role_permissions` 是否插入；执行 `redis-cli --scan --pattern "user:permissions:*" | xargs redis-cli DEL`。

### 坑 2：迁移脚本第二次执行失败

**原因**：`INSERT INTO permissions` 触发 `code` 唯一约束冲突。  
**解决**：脚本顶部加 `DELETE FROM permissions WHERE code IN (...)`，或使用 `INSERT IGNORE`。

### 坑 3：`/api/admin/member/*` 一挂权限全部 403

**原因**：当前 P0 七大模块**不含 member**，挂的 code 在权限表里不存在。  
**解决**：先建 `member` 模块的全套权限码（参考 006 脚本结构），绑定 admin 角色后再挂。

### 坑 4：用户登录后权限没刷新

**原因**：权限走 service 实时查表 + redis 缓存（TTL 3600s），修改角色绑定后缓存未过期。  
**解决**：调用 `/api/auth/me` 强制刷新前端上下文；或让用户重新登录。管理端手动清 redis：`redis-cli --scan --pattern "user:permissions:*" | xargs redis-cli DEL`。

> 注意：`user_type` 字段已废弃（v2.9），JWT payload 中不再包含 `userType`。所有权限判定统一走 RBAC 角色码。
