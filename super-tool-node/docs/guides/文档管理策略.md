> 文档版本: v1.0 | 生成日期: 2026-04-01 | 分类: guides

## 一、文档存储位置

所有 Agent 对话输出的文档及项目相关文档统一保存至：

```
super-tool-node/docs/
```

**注意**: 文档与代码分离管理。代码位于 `node-demo/`（未来迁移至 `super-tool-node/`），文档统一位于 `super-tool-node/docs/`。

## 三、文档分类说明

| 分类 | 目录 | 说明 | 示例 |
|------|------|------|------|
| **分析报告** | `analysis/` | 项目评估、技术调研、性能分析 | 现状评估、技术对比 |
| **架构设计** | `architecture/` | 系统架构、模块设计、技术方案 | 架构图、分层设计 |

| **变更日志** | `changelog/` | 月度变更记录、版本发布说明 | 功能变更记录 |

## 四、文档命名规范

### 4.1 文件命名

```
[主题]-[子主题].md     # 中文命名，使用连字符分隔
ADR-[编号]-[标题].md   # 架构决策记录
YYYY-MM.md            # 变更日志按月份
```

### 4.2 文档头部模板

每个文档必须包含以下头部信息：

```markdown
# 文档标题

> 文档版本: v1.0 | 生成日期: YYYY-MM-DD | 分类: [analysis|architecture|api|database|deployment|guides|decisions|changelog]
> 作者: [人工/Agent名称] | 状态: [草稿|评审中|已发布|已废弃]

---
```

### 4.3 Agent 文档标识

由 Agent（如 CodeBuddy、Claude、Cursor）生成的文档需在头部标注来源：

```markdown
> 生成方式: Agent 自动生成 | Agent: CodeBuddy
> 人工审核: [待审核/已审核-审核人]
```

## 五、文档维护流程

### 5.1 创建流程

```
1. Agent 生成文档 → 保存到对应分类目录
2. 更新 docs/README.md 索引
3. 标记为"待审核"状态
4. 人工评审后标记为"已发布"
```

### 5.2 更新流程

```
1. 修改文档内容
2. 更新文档版本号（v1.0 → v1.1）
3. 记录到 changelog/ 对应月份文件
4. 需要时重新评审
```

### 5.3 废弃流程

```
1. 在文档头部标注"已废弃"状态
2. 添加废弃说明和替代文档链接
3. 不删除文件，保留历史记录
```

## 六、文档质量标准

| 维度 | 要求 |
|------|------|
| **完整性** | 包含背景、目的、方案、实施步骤 |
| **准确性** | 代码示例可运行、配置可复制 |
| **时效性** | 与代码保持同步，过期标记废弃 |
| **可读性** | 使用 Markdown 格式、适当分层 |
| **可搜索** | 有清晰的标题和关键词 |

## 七、与代码的关联

| 场景 | 文档位置 | 代码位置 |
|------|---------|---------|
| 新增接口 | `docs/api/modules/` 中添加说明 | `app/router/` + `app/controller/` |
| 新增数据表 | `docs/database/表结构设计.md` 更新 | `database/migrations/` |
| 架构变更 | `docs/decisions/` 新增 ADR | 对应代码目录 |
| 环境变量新增 | `docs/deployment/环境变量说明.md` 更新 | `.env.example` |
