# 2026-05 变更日志

## 2026-05-08 — 用户收藏工具模块上线

### 新增功能

**数据层：**
- 新增 `user_tool_favorites` 表（(user_id, tool_id) 联合唯一、sort 手动排序、外键 CASCADE）
- Migration：`database/005_add_user_favorites.sql`（v2.4.0）

**Model：**
- `app/model/user_tool_favorite.ts` — `UserToolFavorite` 模型 + belongsTo(User/Tool)

**Service：**
- `app/service/favorite.ts` — `FavoriteService`
  - `addFavorite` / `removeFavorite`（幂等，409 / 404 明确语义）
  - `listFavorites`（分页 + `$tool.xxx$` outer where 支持 keyword 模糊 + categoryCode 过滤）
  - `listFavoriteCodes`（轻量 code 集合，供前端批量标注）
  - `checkFavorited`（单工具收藏态）
  - `reorderFavorites`（事务批量 UPDATE sort = (i+1)*10）

**Controller：**
- `app/controller/favorite.ts` — 6 个 action（create/destroy/index/codes/check/reorder）

**Router：** 新增 6 条路由（精确路径在 `:toolCode` 通配前声明）

**错误码：** 新增 `1009xx` 区间（4 条）

**接口清单（6 个，均需登录）：**
- `POST /api/favorites` — 收藏工具
- `DELETE /api/favorites/:toolCode` — 取消收藏
- `GET /api/favorites` — 分页列表（支持 keyword/categoryCode）
- `GET /api/favorites/codes` — 已收藏 code 集合（轻量）
- `GET /api/favorites/check/:toolCode` — 单工具收藏态
- `PUT /api/favorites/reorder` — 手动拖拽排序

### 设计决策

1. **物理删除**：取消收藏直接 DELETE，不做软删；联合唯一索引 `(user_id, tool_id)` 保证幂等
2. **手动排序**：`sort` 使用 10 步长间隔，便于未来头插 / 中插而无需整体 rebase
3. **冗余 `tool_code`**：避免 codes / destroy 等轻量接口额外 JOIN，外键 CASCADE 兜底一致性
4. **接口拆分**：`GET /codes` 与 `GET /` 分离，工具列表页用 codes 一次性标注、个人中心用 list 拉分页详情
5. **路由顺序**：所有精确路径（`/codes`、`/reorder`、`/check/:toolCode`）必须在 `/:toolCode` 通配路由之前声明
6. **Sequelize 细节**：`findAndCountAll` 使用 `distinct:true + col:'id'` 保证 count 正确；工具过滤条件使用 `$tool.xxx$` outer where 语法，规避 `subQuery:false` 下 include.where 的边界问题
7. **事务管理**：使用 `this.ctx.model.transaction(async (t) => {...})`，与 `member.ts` 风格一致

## 2026-05-06 — 工具管理模块上线

### 新增功能

**数据层：**
- 新增 `tool_categories` 表（11 个预置分类）
- 新增 `tools` 表（233 个预置工具，来源 `test1.js`）
- Migration：`database/004_add_tools_system.sql`（v2.3.0）
- 种子生成脚本：`scripts/build-tools-seed.js`

**Model：**
- `app/model/tool_category.ts` — `ToolCategory` 模型
- `app/model/tool.ts` — `Tool` 模型 + 与 `ToolCategory` 的关联

**Service：**
- `app/service/tool.ts` — `ToolService`
  - H5 端：`getHomeData`（聚合/分页双模式）、`getFeatureTools`、`getMemberTools`、`checkToolAccess`
  - 管理端：分类 CRUD、工具 CRUD、`batchPublish` 批量发布/下架
  - Redis 缓存治理：`tool:categories:all` (600s)、`tool:home:aggregate` (300s)

**Controller：**
- `app/controller/tool.ts` — H5 端 4 个 action
- `app/controller/admin/tool.ts` — 管理端 10 个 action

**Router：** 新增 14 条路由（H5 端 4 条 + 管理端 10 条）

**错误码：** 新增 `1008xx` 区间（9 条工具模块错误码）

**接口清单：**

H5 端（4 个）：
- `GET /api/tools/home` — 首页聚合/分页
- `GET /api/tools/feature` — 特色功能 Tab
- `GET /api/tools/member` — 会员专属 Tab
- `GET /api/tools/:code/access` — 使用前权限校验（需登录）

管理端（10 个）：
- `GET/POST /api/admin/tool-categories`
- `PUT/DELETE /api/admin/tool-categories/:id`
- `GET/POST /api/admin/tools`
- `GET/PUT/DELETE /api/admin/tools/:id`
- `PUT /api/admin/tools/batch-publish`

### 设计决策

1. **权限模型**：使用 `required_level_code` + `require_paid` 两个正交字段，而非权限码体系
2. **主键风格**：自增 `id` + unique `code`（与 `member_levels` 等既有表一致）
3. **H5 首页接口**：双模式单接口（无参聚合、有参分页），查询 `/home` 不挂鉴权；使用工具时才通过 `/access` 懒校验
4. **Tab 筛选**：严格口径，允许一个工具同时出现在特色 Tab 和会员专属 Tab
